REDUCE BEFORE REASONING

縮小工具輸出再交給模型

工具端多做一行過濾，可能替模型省下數千行日誌。這一章把查詢、搜尋、聚合、去重與 Artifact 視為第一級 Context 控制，而不是把原始結果全部丟給模型。

80–105 分鐘8 個完整段落實例＋模板＋作業品質優先

LEARNING OUTCOME

完成本章後，你能為每個工具設定輸出預算，使用 Filter、Projection、Top-K、聚合與 Artifact，把大量中間資料縮成附帶證據定位的結構化結果。

IMPORTANT BOUNDARY

縮減不能抹去支持結論的證據。重要來源、錯誤樣本、統計分母與不確定性必須保留；原始結果可外置，但要有可回溯 ID。

01

MEASURE THE RETURN

一個搜尋或日誌工具可以瞬間吞掉整個 Context Budget

工具結果常比提示詞大：搜尋回傳二十篇摘要、SQL 查出數萬列、測試日誌包含成功訊息、瀏覽器回傳完整 DOM。若直接加入歷史，下一回合還可能再次重送。

為每個工具記錄回傳位元組、估計 Token、結果數、重複率與模型實際引用率。若模型最後只用三列，就應在工具端找出選擇規則；若需要全文證據，則將全文存成 Artifact，只送索引與必要片段。

RAW原始回傳

常含大量重複、欄位與格式噪音

REDUCE工具端縮減

過濾、投影、排序、聚合與去重

MODEL語意判斷

只接收高訊號結構與必要證據

ARTIFACT完整結果外置

保留 ID、位置、雜湊與重新讀取方式

圖解｜工具輸出是主要輸入來源 把每一步的輸入、判斷與輸出分開，才看得見真正可以縮減的地方。

02

RETURN ONLY MATCHES AND FIELDS

限制列數之前，先把條件與欄位說清楚

資料查詢先用伺服器端 WHERE、時間窗、權限與狀態過濾，再只投影決策需要的欄位。搜尋工具加入路徑、檔案類型與精確模式；日誌先依 service、level、request_id 與時間縮小。

不要把十萬列抓回應用再請模型找錯誤。能由資料庫、搜尋引擎或程式確定的條件，應在模型之前執行。回傳附上 applied_filters 與 total_matches，讓模型知道結果為何縮小、是否還有未讀資料。

{
  "items": [...],
  "applied_filters": {...},
  "total_matches": 1834,
  "returned": 20,
  "truncated": true
}
FILTER縮小資料列

時間、狀態、權限、路徑與條件

PROJECT只取必要欄位

省略大文字、內部 Metadata 與重複欄位

LIMIT限制結果數

搭配排序，不任意截前幾筆

META說明縮減範圍

條件、總命中、是否截斷與下一頁

圖解｜先 Filter 再 Projection 把每一步的輸入、判斷與輸出分開，才看得見真正可以縮減的地方。

03

RANK BEFORE LIMIT

前十筆若沒有排序定義，只是隨機省略

Top-K 應說明依什麼排序：相關性、時間、嚴重度、影響、權威性或組合分數。對除錯日誌，最新不一定最重要；對研究來源，語意相似不一定最權威。模型需要知道排序依據與分數，才能判斷是否擴張。

採分層取樣能避免單一來源占滿結果，例如每個模組保留最高兩筆、每種錯誤保留代表樣本、每個來源限制一段。若 Top-K 無法覆蓋必要多樣性，先分群再取代表，而不是把 K 一路調大。

SCORE明確排序函數

相關、嚴重、時間、權威與業務影響

GROUP先分群

模組、錯誤類型、來源與使用者

SAMPLE每群代表

保留多樣性，不被高頻重複淹沒

EXPAND不足才增加

帶著缺口與新條件做第二次查詢

圖解｜Top-K 必須搭配排序理由 把每一步的輸入、判斷與輸出分開，才看得見真正可以縮減的地方。

04

COLLAPSE REPETITION

模型不需要看同一個錯誤出現五千次

日誌與搜尋結果應用正規化鍵去重，例如錯誤類型、堆疊首行、服務與版本；回傳次數、首次、最後、影響使用者與代表樣本。數值資料先統計總數、分布、Top類別與異常，再按需取得原始列。

聚合不可隱藏分母與例外。『90% 成功』應附總數、時間窗與失敗類型；去重錯誤仍要保留不同版本或不同上下文的代表樣本。模型接收的是可決策摘要，而不是沒有證據的單句結論。

NORMALIZE建立重複鍵

錯誤、來源、版本與重要上下文

COUNT次數與時間

總數、首次、最後與趨勢

SAMPLE代表證據

每群保留少量原始樣本與定位

OUTLIER例外另列

不要讓少量高影響事件被平均掩蓋

圖解｜去重與聚合 把每一步的輸入、判斷與輸出分開，才看得見真正可以縮減的地方。

05

REFERENCE INSTEAD OF REPLAY

完整報告留在檔案，模型只帶 Manifest 與相關片段

測試完整輸出、長 PDF、資料匯出與大 Diff 適合保存為 Artifact。上下文只放 Artifact ID、內容類型、大小、產生時間、雜湊、摘要、關鍵位置與如何局部讀取。後續需要更多證據時再按 ID 取段落。

Artifact 要有權限、保存期限與版本；摘要與原始內容必須綁定，避免摘要更新後引用舊檔。若最終交付要求完整檔案，模型可以生成或修改 Artifact，但不用把全文再次輸出到聊天與下一回合。

STORE保存完整內容

檔案、物件儲存或受控工作區

MANIFEST小型描述

ID、類型、大小、版本、雜湊與摘要

POINTER證據定位

頁碼、行號、查詢條件或區塊 ID

FETCH按需局部讀取

只取當前判斷所需範圍

06

CODE THE REDUCTION

過濾、Join、排序與驗證不必每一步都請模型判斷

當工作是有界、規則清楚的過濾、Join、排名、去重、聚合或 Schema 驗證，可用程式在工具層連續處理多個結果，只把小型結構交給模型。這可減少大型中間輸出反覆進出模型。

若每個結果都可能改變下一步語意決策、操作需要核准、或最終輸出必須保留原生引用與 Artifact，直接工具呼叫較合適。選擇標準是工作形狀，不是『呼叫很多就程式化』；兩條路都要以最終完整性、Token、延遲、呼叫與重試評測。

GOOD FIT可預測資料處理

Filter、Join、Rank、Dedup、Aggregate、Validate

MODEL保留語意判斷

需求解讀、權衡、例外與最終解釋

DIRECT每步需新判斷

結果改變路線、需要核准或保留原生證據

EVAL比較最終答案

資源少只有在品質仍通過時才算改善

圖解｜程式化處理適合可預測步驟 把每一步的輸入、判斷與輸出分開，才看得見真正可以縮減的地方。

07

RETURN STRUCTURED EVIDENCE

工具不能只回一段散文，讓 Agent 猜是否完整

一致的工具結果至少包含 status、summary、items、evidence、truncated、next_cursor 與 error。不同工具可以有不同資料欄位，但成功、部分成功、空結果與錯誤應能被可靠區分。

部分結果不能偽裝成完整答案。若因權限、預算或 Timeout 截斷，回傳 missing、reason 與 next_allowed_action。Agent 才能決定是否擴張、改查詢、詢問使用者或停止，而不是重複同一呼叫。

{
  "status": "partial",
  "summary": "找到 3 類主要錯誤",
  "evidence": [...],
  "missing": "較早 24 小時尚未掃描",
  "next_allowed_action": "fetch_next_page"
}
STATUS完整狀態

ok、partial、empty、error

SUMMARY可決策摘要

包含範圍、主要結果與不確定性

EVIDENCE原始定位

ID、來源、行頁與代表樣本

MISSING明確缺口

截斷、權限、Timeout與允許下一步

圖解｜輸出契約要包含缺口 把每一步的輸入、判斷與輸出分開，才看得見真正可以縮減的地方。

08

BUDGET EVERY RETURN

每個工具都有預設、最大與擴張條件

為每個工具定義預設結果數、最大字元或 Token、必要欄位、排序、去重、Artifact策略、截斷標記與擴張方式。高頻工具優先做，因為小幅縮減會乘上大量呼叫。

以三個大型真實案例比較 Raw 與 Reduced：模型是否仍能回答、引用是否正確、總 Token、延遲、呼叫與重試。若 Reduced 需要多次來回才取得原本必要證據，可能縮得太小；調整的是預算與分層，而不是回到無上限。

DEFAULT正常回傳預算

涵蓋多數任務的最小結果

MAX硬上限

防止極端查詢拖垮上下文

EXPAND受控擴張

Cursor、指定群組、Artifact片段

PROVE證據仍完整

用固定案例比較答案、引用與總成本

FIELD ASSIGNMENT

把一個大型工具輸出縮成契約

可使用日誌、搜尋、SQL、測試輸出或大型 Diff。

  1. 00–15

    量測原始結果大小、列數、欄位、重複與模型引用率。

  2. 15–30

    設計 Filter與聚合排序、分群、去重、代表樣本與必要欄位。

  3. 30–45

    建立 Artifact Manifest全文外置，保留 ID、摘要、雜湊與局部讀取。

  4. 45–60

    跑 Raw／Reduced Eval比較證據、Token、呼叫與延遲。

CHECK YOUR MODEL

先回答，再展開。

限制結果數就算完成輸出縮減嗎？

不夠。要先定義過濾、排序、欄位、去重與截斷資訊，否則只是任意丟資料。

聚合後還需要原始樣本嗎？

通常需要。保留分母、例外與代表證據，完整內容可存 Artifact。

什麼工作適合程式化處理？

有界且可預測的過濾、Join、排序、去重、聚合與驗證。

Partial 結果為什麼要明確標示？

避免 Agent 把截斷資料當完整結論，或無目的地重複呼叫。

Reduced 需要更多工具呼叫怎麼辦？

計算完整任務總成本；若過度縮小造成多輪擴張，調整預設預算與分層。

COURSE OUTLINE / CHAPTER 08

MAKE THE LOOP TERMINATE

減少重試、空轉與無效確認

最昂貴的 Agent 往往不是回答太長，而是不知道何時停止：重試相同錯誤、重做已完成工具、反覆確認安全操作，或在沒有新證據時繼續探索。

80–100 分鐘8 個完整段落實例＋模板＋作業品質優先

LEARNING OUTCOME

完成本章後，你能設計完成條件、階段上限、Retry Budget、冪等與錯誤分類，並建立核准邊界和結構化失敗輸出，讓 Agent 能停、能交接、也能安全恢復。

IMPORTANT BOUNDARY

停止條件不能逼 Agent 在資訊不足時假裝成功。對高風險操作，寧可明確失敗並請求必要授權，也不要為了省一回合越過安全或品質邊界。

01

MODEL THE LOOP

看、想、做、驗證每一階段都要有離開條件

Agent Loop 可以拆成理解、取得證據、執行、驗證、完成或失敗。每個狀態列出允許動作、必要輸入、產生輸出與轉移條件。若只寫『持續直到完成』，模型難以判斷何謂進展。

加入 progress signal：新證據、新 Artifact、測試變化、錯誤類別改變或未完成清單縮小。若一個回合沒有產生新訊息，下一回合不應原樣重複；要改策略、回報缺口或停止。

02

DEFINE DONE

『看起來可以』不能讓 Agent 安全停止

完成條件使用模型外可檢查的證據：必要檔案存在、測試通過、指定欄位完整、來源已引用、使用者核准已取得、外部操作回傳成功 ID。把 Must-have 與可選改善分開，避免完成後繼續潤飾。

對研究任務，完成可能是回答所有問題且每項有來源；對程式任務，是實作、相關測試與變更摘要；對資料任務，是結果、分母、時間窗與異常說明。Agent 在通過 Done Checklist 後直接輸出，不再自我反思多輪。

ARTIFACT交付物存在

檔案、報告、資料或提交預覽

EVIDENCE驗證通過

測試、查詢、引用或回傳 ID

OPEN必要缺口為零

Must-have 未完成就不能成功

OPTIONAL改善不阻止完成

延伸、潤飾與額外方案有獨立預算

03

RETRY ONLY TRANSIENT FAILURES

相同輸入重跑永久錯誤，只會得到更貴的相同結果

將錯誤分為 transient、rate-limit、invalid-input、permission、not-found、conflict、unsafe與unknown。只有明確暫時性錯誤允許自動重試；輸入錯誤先修正參數，權限錯誤請求授權，找不到則改查詢或回報，安全拒絕不可用重試繞過。

工具回傳 retryable 與 retry_after，Agent 不自己從散文猜測。每次重試必須記錄 attempt、前次錯誤與這次改變；若沒有任何新條件，就不應重試。unknown 預設不無限循環，先一次診斷或直接失敗。

retry_allowed = error.retryable
  and attempts < retry_budget
  and (input_changed or retry_after_elapsed)
  and operation_is_idempotent
TRANSIENT可有限重試

網路暫斷、上游 5xx、明確超時

RATE依 Retry-After

退避、抖動與全域配額

INPUT先修正再呼叫

缺欄位、格式或範圍，原樣重試無效

PERMISSION停止並取得授權

不可換工具或重試來繞過

04

LIMIT ATTEMPTS AND TIME

重試上限要按工具、階段與整個任務一起計算

單工具最多重試兩次並不代表安全：十個工具各兩次仍可能非常昂貴。設定 call-level、stage-level與run-level三層預算，並包含 Token、時間與外部費用。任一上限到達即轉入降級或失敗。

使用指數退避與抖動處理暫時失敗，但背景等待也受總時間限制。高成本工具或付費 API 的重試更嚴格；非冪等寫入原則上不能自動重試，除非使用 idempotency key 且服務確認前次未重複執行。

STAGE階段總額

RUN任務硬上限

總 Token、時間、費用與外部操作

FALLBACK到頂後行為

降級、保存 Checkpoint 或結構化失敗

05

MAKE REPLAY SAFE

不確定上次是否成功，往往會造成重複寫入與額外查詢

對建立訂單、發送訊息、部署與付款等動作，使用 idempotency key、operation ID與可查詢狀態。Agent 在 Timeout 後先查 operation 狀態，而不是直接重送。讀取工具天然較容易重試，寫入工具需明確設計。

每個步驟保存輸入摘要、預期 Artifact、實際回傳 ID與完成標記。恢復時從最後一個已驗證 Checkpoint繼續，不重做所有前置工具。這同時降低 Token、外部費用與資料重複風險。

WRITE非冪等預設不重試

需要明確確認或服務保證

06

ASK ONLY FOR MATERIAL CHOICES

頻繁確認會新增回合與重送歷史，但沉默越權更糟

把讀取診斷、範圍內可逆修改、外部寫入、付費、破壞性操作與範圍擴張分級。使用者要求『建置／修正』後，安全的本機讀取、編輯與測試通常不必逐步問；對外發布、刪除或付費則在具體預覽後確認。

詢問時合併真正需要的決策，提供影響與預設建議，不要每個小步都問。能從現有檔案、設定或測試確認的資訊先自行檢查。核准後把已允許範圍寫入狀態，後續不重複問同一件事。

AUTO安全範圍內繼續

讀取、診斷、可逆修改與相關測試

BATCH合併實質選擇

架構、資料、行為與使用者可見差異

07

FAIL WITH A CONTRACT

清楚的失敗比昂貴的模糊循環更有價值

當預算用盡、缺必要資料、權限不足或外部服務持續失敗，Agent 應回傳 status、已完成、證據、阻塞、嘗試過的方法、未執行動作、保存的 Artifact、需要的最小輸入與建議下一步。

這份失敗輸出可直接成為 Checkpoint，讓使用者補資料後續接，而不用重新探索。不要把錯誤堆疊全貼進最終答案；保存 Artifact 並附摘要與定位。也不要只說『無法完成』，那會迫使下一次從零開始。

SHIP THE TERMINATION POLICY

讓每一個回合都能回答：有何新進展？還剩多少預算？

BEFORE / AFTER

同一個 403 重試六次，Agent 為什麼停不下來？

WASTEFUL

工具只回『request failed』，Prompt 又要求『不要放棄直到成功』。

OPTIMIZED

錯誤契約標示 permission、retryable=false；Loop Guard 停止並回傳缺少的最小授權。

WHY IT WORKS

避免六次無效呼叫，也不以換工具方式繞過權限。

CHECK YOUR MODEL

先回答，再展開。

『持續直到完成』為什麼危險？

若沒有完成與進展定義，Agent 可能無限重試、重複工具或延伸非必要工作。

哪些錯誤適合自動重試？

明確暫時性、受預算限制且操作可安全重播的錯誤。

單工具重試上限足夠嗎？

不足。還要有階段與完整任務總上限，避免多工具各自重試累積。

如何減少確認又不降低安全？

把授權按影響分級，範圍內安全動作直接進行，外部或不可逆操作在具體預覽後確認。

失敗輸出應該包含什麼？

狀態、已完成與證據、阻塞、已嘗試、Artifact、所需最小輸入與續接下一步。

COURSE OUTLINE / CHAPTER 05

REMEMBER WITHOUT REPLAYING

對話記憶、摘要與壓縮

記憶的目的不是保存所有對話，而是讓下一個回合取得正確的現在狀態。用 Checkpoint、分層記憶與壓縮保留決策，才能避免長任務反覆重播探索過程。

80–105 分鐘8 個完整段落實例＋模板＋作業品質優先

LEARNING OUTCOME

完成本章後，你能區分短期狀態、長期偏好與外部 Artifact，設計可驗證的 Checkpoint，決定何時摘要、壓縮、淘汰或重新開啟工作階段。

IMPORTANT BOUNDARY

摘要會遺失資訊。高風險決策、合約、法規、精確數字與安全限制必須保留權威來源或可回溯定位，不能只留下模型自行生成的摘要。

01

STORE STATE NOT TRANSCRIPTS

真正需要延續的是決策狀態，不是每一句對話

逐字歷史能保留最多資訊，卻也保留所有岔路、錯誤、重複與已淘汰方案。對長任務而言，下一回合更需要知道目標、硬限制、已完成、有效證據、未解問題與下一步。

把歷史分成三層：當前 Working Set、可跨回合保留的 Checkpoint、可按需讀取的原始 Artifact。只有仍會改變下一個決策的內容留在 Working Set；其餘移到外部並保存定位。

WORKING當前工作集

下一個決策立刻需要的內容

CHECKPOINT可續接狀態

目標、決策、證據、未完成與下一步

ARTIFACT原始證據

檔案、日誌、Diff、查詢與完整報告

TRANSCRIPT探索歷史

完成後通常不必逐字重送

圖解｜記憶不是歷史全文 把每一步的輸入、判斷與輸出分開，才看得見真正可以縮減的地方。

02

MATCH MEMORY TO LIFETIME

使用者偏好、專案規則與本回合暫存不該混在一起

短期記憶只服務目前 Run；工作階段記憶支援同一目標的多輪；專案記憶保存架構決策與規範；使用者記憶則只存明確、穩定且合適的偏好。不同層有不同擁有者、權威性與到期條件。

不要把一次任務中的暫時假設升級成永久記憶，也不要把敏感輸入默認長期保存。每筆長期記憶至少要有來源、建立時間、適用範圍、信心與更新方式；能從權威檔案重新取得的資訊，優先保存索引而非複製全文。

TURN回合暫存

工具中間結果與待驗證假設

SESSION同一任務

決策、進度、風險與下一步

PROJECT專案規則

架構決策、標準與擁有者

USER穩定偏好

只保存明確允許且長期有用的資訊

03

WRITE A HANDOFF

好的摘要讓新 Agent 不讀原對話也能安全接手

Checkpoint 應採固定欄位：任務目標、不可違反限制、已完成與證據、已決定與理由、未完成、已知失敗、重要 Artifact、唯一下一步。每一項決策最好連回檔案、行號、測試或來源 ID。

避免寫『大致完成』『應該沒問題』這類無法驗證的敘述。區分事實、推論與假設；未驗證就明確標記。Checkpoint 是狀態 API，不是漂亮摘要，因此欄位完整與可接續比文筆重要。

04

COMPRESS WITH PRIORITIES

先刪探索噪音，最後才碰決策與限制

壓縮順序可以固定：先移除禮貌語與重複，再刪除已淘汰方案的細節，將長工具輸出換成結果與定位，把已完成操作換成驗證摘要；目標、硬限制、最終決策、證據來源與未完成事項最後保留。

摘要後做一次完整性檢查：原始任務的 Must-have 是否仍存在？每個關鍵決策能否回到來源？未解問題是否被誤寫成結論？如果不能，摘要不能取代原始狀態，只能作為索引。

DROP 1重複與禮貌

最先刪除，不影響任務狀態

DROP 2淘汰探索細節

保留淘汰理由，不重播全文

SUMMARIZE工具與完成操作

保留結果、證據位置與錯誤

PRESERVE目標、限制、決策、未完成

最後保留並做完整性檢查

05

TRIGGER AT BOUNDARIES

不要等到窗口爆滿才臨時摘要

適合建立 Checkpoint 的時點包括：完成一個階段、工具結果大量增加、分支方案已做出選擇、交給子 Agent、準備模型切換、接近 Context Budget 或工作暫停。這些都是天然的語意邊界。

若平台提供 Compaction 或狀態延續能力，仍要監控壓縮前後 Token 與品質。平台壓縮不等於應用不必設計記憶：哪些 Artifact 保存、哪些決策需可追溯、哪些資料不得長期留存，仍是你的責任。

MILESTONE階段完成

把探索收束成結果與證據

GROWTH上下文快速增長

工具、檔案與錯誤達到預算

HANDOFF模型或 Agent 切換

建立可獨立接手的狀態契約

PAUSE工作暫停

保存下一次可立即執行的起點

06

START FRESH WHEN THE GOAL CHANGES

舊上下文不相關時，延續本身就是浪費

若使用者目標已改變、先前假設被推翻、工具與資料版本大幅更新，或歷史中充滿互相衝突的狀態，新的工作階段通常比繼續壓縮更乾淨。重新開局時只攜帶經驗證的專案規則與最新 Checkpoint。

不要因為怕遺失上下文就讓所有任務永遠留在同一對話。相反地，也不要在同一未完成任務中頻繁重開，造成反覆建立背景。判斷標準是：舊內容中仍有多少會影響下一個決策，以及能否用一份短 Checkpoint完整取代。

CONTINUE目標與限制穩定

沿用狀態可避免重新建立背景

COMPACT任務相同但歷史過長

用 Checkpoint取代探索細節

FRESH目標或版本已變

只帶最新權威狀態重新開始

ARCHIVE保留可回溯證據

舊對話外置，不永久進入新上下文

07

REVALIDATE MEMORY

過期或錯誤記憶會讓便宜的上下文產生昂貴錯誤

長期記憶若沒有來源與版本，可能在專案改版後繼續提供舊介面、舊費率或已撤銷政策。讀取記憶時依任務風險決定是否回到權威來源重新驗證；有衝突時以最新權威資料為準並更新或淘汰舊記憶。

也要避免模型把未確認推論寫成使用者偏好。只有使用者明確表達、且長期保存合理的資訊才進入個人記憶。建立可查看、修正與刪除的機制，並限制敏感資訊。Token 效率不能凌駕資料治理。

SOURCE每筆記憶有來源

檔案、使用者明示或權威系統

SCOPE適用範圍

專案、版本、任務與角色

TTL到期與重驗證

高變動內容更短，使用前可刷新

CONTROL可查看與淘汰

錯誤、敏感或不再需要時移除

08

SHIP THE MEMORY CONTRACT

明確寫出保存什麼、多久、如何驗證與何時刪除

Memory Policy 列出每一層的資料類型、擁有者、保存位置、大小上限、權威來源、更新與淘汰條件。再附一份 Checkpoint Schema 與兩個案例：長任務階段壓縮、目標改變後重新開局。

驗證方式是把 Checkpoint 交給一個沒有原始歷史的新執行者，觀察能否正確說明當前狀態並完成下一步。若需要回頭讀大部分舊對話，Checkpoint 還不夠；若它自信地忽略關鍵限制，則壓縮過度。

POLICY記憶分層表

資料、範圍、大小、來源與到期

SCHEMA固定 Checkpoint

欄位完整、可驗證、可接手

TEST冷啟動接手

不給舊對話，檢查是否能安全續作

REVISE補缺口不補全文

只增加真正影響下一步的資訊

BEFORE / AFTER

38 回合對話要交接，該留下什麼？

WASTEFUL

把完整 Transcript 貼給新 Agent，包含 6 個已淘汰方案與 14 次重複錯誤。

OPTIMIZED

留下目標、5 個硬限制、最終決策、3 個 Artifact、2 個未解問題與唯一下一步；原始對話只作外部索引。

WHY IT WORKS

新 Agent 能直接驗證與續作，不必重新讀取整段探索。

FIELD ASSIGNMENT

壓縮一段至少 15 回合的工作

使用非敏感或匿名內容，保留原始版本作比較。

  1. 00–15

    標記狀態找出目標、限制、決策、完成、未完成與證據。

  2. 15–30

    寫 Checkpoint依固定 Schema 產生可接手版本。

  3. 30–45

    冷啟動測試只給 Checkpoint，請新執行者說明狀態與下一步。

  4. 45–60

    修正 Memory Policy補足遺失欄位，設定到期與重新驗證。

CHECK YOUR MODEL

先回答，再展開。

摘要是不是越短越好？

不是。必須保留會改變下一步的目標、限制、決策、證據與未完成事項。

平台有自動 Compaction 就不必設計記憶嗎？

仍需設計。Artifact、權威來源、資料保存與可追溯性是應用責任。

什麼資訊適合長期記憶？

明確、穩定、適合保存且日後會重用的偏好或專案規則，並附來源、範圍與更新方式。

何時應重新開一個工作階段？

目標、假設或資料版本重大改變，舊內容大多不再影響下一決策時。

如何測 Checkpoint 是否足夠？

讓未看原始對話的執行者只用 Checkpoint 接手，檢查是否正確理解並安全完成下一步。

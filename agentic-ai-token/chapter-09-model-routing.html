模型與推理強度分流

最強模型與最高推理強度不是每個步驟的預設答案。真正成熟的系統會依任務難度、風險、可驗證性與失敗成本路由，便宜路徑能完成就不升級。

85–110 分鐘8 個完整段落實例＋模板＋作業品質優先

LEARNING OUTCOME

完成本章後，你能建立任務分級與路由矩陣，控制模型、推理強度和輸出詳細度，設計升級閘門，並用同一 Eval Set比較成本、品質與延遲。

IMPORTANT BOUNDARY

模型能力、名稱、費率與可用設定會變。課程教的是決策框架；正式部署前必須以當前官方文件、帳戶可用性與自己的代表性任務重新評測。

01

CLASSIFY THE WORK

難度、風險與可驗證性比字數更重要

一份長文件摘要可能規則清楚、容易驗證；一句資料遷移問題卻可能高風險且需要深推理。任務分級至少考慮：步驟數、歧義、領域難度、工具依賴、上下文量、錯誤後果與是否有自動驗證。

把流量分成 Routine、Reasoning、High-risk與Unknown。Routine用快速低成本基準；Reasoning需要較強模型或較高推理；High-risk還需額外驗證與可能人工核准；Unknown先做低成本分類與取證，不直接上最高設定。

ROUTINE規則清楚可驗證

分類、抽取、格式與固定流程

REASONING多步與權衡

規劃、除錯、跨來源綜合

HIGH RISK失敗代價高

資料、金錢、安全、法規與正式變更

UNKNOWN先取得訊號

用小步探查，再決定是否升級

02

START WITH THE CHEAPEST PASSING ROUTE

不是選最便宜模型，而是選能通過門檻的最低成本路徑

對每一任務類型，先用較低成本設定跑固定 Eval；若 Must-have通過，再比較更高設定是否帶來有價值的品質增益。若低成本路徑失敗模式集中在少數案例，使用條件式升級，而不是整類流量永遠用最高設定。

路由比較要含總 Token、費用、延遲、成功、重試與人工介入。較便宜模型若頻繁輸出錯誤工具參數或需二次修正，實際 Cost per Success可能更高。最低能力基準是經測試得出，不是依模型標籤猜測。

先測是否通過 Must-have

FAILURE分析失敗群

找出需要更多能力的具體訊號

ROUTE條件式升級

只讓必要任務走昂貴路徑

TOTAL比較完整任務

含重試、工具、延遲與人工

03

SET EFFORT INTENTIONALLY

更多推理只有在品質提升可量測時才值得

推理強度影響模型投入與延遲。對資料抽取、簡單改寫與明確工具路由，較低設定常足夠；對複雜除錯、規劃與高價值審查，較高設定可能提升完整性。不要把最高設定當保險。

從目前可用設定與一級較低設定比較代表任務；記錄哪些任務因降低而失敗、哪些完全無差。將高設定綁定可辨識條件，例如跨五個模組、無自動測試、資料不可回復或需要多來源衝突判斷。

LOW明確可驗證

短分類、抽取、格式與直接工具

MEDIUM一般 Agent 工作

需要規劃、幾個工具與驗證

HIGH困難且品質敏感

複雜權衡、除錯或高價值審查

EVAL以結果決定

低一級若品質持平就不保留昂貴設定

圖解｜推理強度要有用途 把每一步的輸入、判斷與輸出分開，才看得見真正可以縮減的地方。

04

SEPARATE THINKING FROM WRITING

需要深推理，不代表需要長篇答案

模型可能需要充分推理才能給出可靠結論，但使用者只需要決策、證據、風險與下一步。將推理品質與最終文字長度分開設定；對下游程式只回必要欄位，對教學內容才使用較高詳細度。

用明確預算控制章節、點數、字數與表格寬度，並列出不可刪項。不要要求模型展示完整思考過程來證明品質；使用測試、引用、計算與驗收結果作為外部證據。

輸出最多 6 點。
每點保留：決策、必要證據、重大風險、下一步。
省略：開場、重複背景、未採用方案的長篇推演。
REASON內部工作量

依任務難度選擇，不直接決定答案長度

ANSWER使用者真正需要

結論、證據、重大限制與下一步

STRUCTURE下游格式

欄位、段落、字數與表格限制

PROOF外部可驗證

測試、來源、Artifact與檢查，不展示冗長思考

05

ESCALATE WITH EVIDENCE

不要因為模型『不確定』就無條件換最昂貴路徑

升級訊號可以是：必要測試連續失敗、證據相互衝突、工具回傳未知錯誤、風險分類升高、低成本模型評分低於門檻，或任務明確屬於高價值審查。每次升級保留原因與已完成 Checkpoint。

升級後不應從零重跑全部探索。將較低路徑的有效證據、失敗摘要與未解問題交給較強路徑；避免傳遞冗長 Transcript。若升級仍無新證據，使用同一 Run Budget停止。

SIGNAL可觀察觸發

測試、衝突、風險、評分或未知錯誤

HANDOFF精簡狀態

有效證據、失敗、未解問題與下一步

UPGRADE增加能力或推理

只處理低成本路徑未解部分

STOP仍受總預算

升級不是取消所有上限

06

CASCADE THE ROUTES

便宜模型做分類與準備，強模型只做關鍵判斷

常見 Cascade 是：規則或小模型先分類、檢索與清理；中等模型完成一般任務；只有不確定或高風險案例交給強模型。前置步驟應產生小型結構，不要生成長篇中間報告。

串接會增加呼叫，只有在大量流量能在早期退出時划算。計算 pass-through rate：若 90% 任務最後仍升級，前置呼叫只是額外成本；若大多數 Routine能完成，且 Handoff很小，Cascade才有經濟性。

CLASSIFY低成本路由

任務類型、風險與必要工具

SOLVE一般路徑

大多數任務在此完成並驗證

ESCALATE少數困難案例

只攜帶未解部分與證據

RATE觀察穿透率

升級比例過高就重新設計路由

07

KEEP ROUTING STABLE

模型來回升降或重跑不同模型會抵銷所有節省

同一任務一旦升級，不應因單一回合簡單又降級再重建上下文；設定 Route Lock直到階段結束。若需要多模型分工，明確切分準備、決策與驗證，而不是每回合重新分類。

將路由版本、觸發訊號、選擇與結果記錄在 Trace。觀察同一任務模型切換次數、重複工作與 Handoff大小。若路由器本身需要長提示與強模型，可能不如應用程式規則或小型分類器。

LOCK階段內固定路由

避免每回合重新決定與重建上下文

HANDOFF一次清楚交接

分界、資料 Schema與完成條件

TRACE記錄選擇理由

版本、訊號、模型與結果

SIMPLIFY路由器也要便宜

可用規則解決就不必強模型

08

SHIP THE ROUTER

把任務類型、風險、設定、升級與降級寫成可測規則

矩陣至少含任務類型、預設模型級別、推理強度、輸出預算、必要工具、品質閘門、升級訊號、最大升級次數與失敗行為。每個格子都要能對應 Eval。

用代表任務比較 Single-strong、Single-efficient與Cascade三種架構。先看 Must-have與關鍵風險，再比較每成功任務成本與P95延遲。保留逐任務結果，避免平均值掩蓋某類嚴重回歸。

FIELD ASSIGNMENT

建立三層 Model Routing Matrix

不必綁定品牌名稱，先用 Efficient／Balanced／Frontier三層。

  1. 00–15

    分類任務難度、風險、可驗證性與真實流量比例。

  2. 15–30

    設定預設路徑模型級別、推理、輸出與工具。

  3. 30–45

    定義升級訊號、Handoff、最大次數與失敗行為。

  4. 45–60

    跑三架構 Eval比較品質、成本、P95與穿透率。

CHECK YOUR MODEL

先回答，再展開。

最便宜模型就是最省的選擇嗎？

不一定。若成功率低、工具錯誤多或頻繁升級，每成功任務成本可能更高。

深度推理一定要長答案嗎？

不需要。推理強度與最終輸出詳細度應分開控制。

何時適合 Cascade？

大部分任務能在早期便宜路徑完成，且少數升級可用精簡狀態交接時。

為什麼要 Route Lock？

避免同一階段來回切換模型、重建上下文與重複工作。

如何選推理強度？

從可用基準與較低一級比較，只有代表任務有量測品質增益才保留較高設定。

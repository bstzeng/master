PARALLEL IS NOT FREE

多 Agent 到底省不省 Token

多 Agent 可以縮短牆鐘時間、增加獨立驗證或平行蒐集，但每一個 Agent 都有自己的提示、工具、歷史與回報。要省 Token，分工必須減少重複，而不是複製工作。

90–115 分鐘8 個完整段落實例＋模板＋作業品質優先

LEARNING OUTCOME

完成本章後，你能判斷任務是否可平行拆分，估算協調與複製成本，設計最小子任務包與 Handoff Schema，並比較單 Agent 與多 Agent 的品質、時間和總 Token。

IMPORTANT BOUNDARY

多 Agent不會擴大使用者授權。每個子 Agent只能執行原任務範圍內的動作；外部寫入、破壞性或昂貴操作仍依原核准邊界處理。

01

TIME QUALITY OR TOKENS

多 Agent最明確的收益通常是時間，不是 Token

平行 Agent能同時進行獨立研究，降低牆鐘時間；不同角色可提供交叉檢查，提升品質；但每個 Agent都會消耗自己的上下文。Token是否下降，取決於分工是否讓每個 Agent看到更少資料、避免重複探索或降低失敗。

在設計前先選主要目標：速度、品質還是成本。若目標是速度，可以接受總 Token增加但設上限；若目標是成本，就需要證明子任務的上下文總和與協調成本小於單 Agent完整流程。不要用『更Agentic』當理由。

TIME降低牆鐘時間

乾淨獨立工作平行執行

QUALITY獨立檢查

不同證據或專長降低單一路徑盲點

TOKENS只有在減少重複時

小上下文、少探索、較低失敗率

COST協調也要加總

拆分、Handoff、回報與統整

02

CHECK THE DEPENDENCIES

乾淨分支可以平行，連續決策不應硬拆

適合拆分的例子：不同模組的獨立檢查、不同資料源研究、互不重疊的章節草稿、獨立測試。若 B需要A的語意結果才能決定做什麼，平行只會讓B猜測或重做。

畫 Dependency Graph，標記共享輸入、前置結果、寫入衝突與統整規則。只有彼此依賴少、交付可用固定 Schema描述、且沒有競爭同一檔案或外部資源的分支，才適合平行。其他工作以單 Agent或串接完成。

INDEPENDENT可平行

輸入清楚、輸出可合併、無共享寫入

SEQUENTIAL需串接

後一步依賴前一步語意判斷

SHARED WRITE容易衝突

同一檔案、資料列或外部狀態

MERGE事先定義

去重、優先序、衝突與缺口

03

ACCOUNT FOR COPIES

共享背景完整複製 N 份，是多 Agent最常見的 Token乘數

多 Agent成本粗估為：協調者輸入與輸出＋所有子 Agent輸入與輸出＋工具結果＋統整。若一份20k背景交給五個 Agent，就有100k輸入起點，尚未計算各自研究。

將共享資料分成三層：所有 Agent需要的短任務契約、各分支專屬內容、可按需查詢的公共 Artifact。協調者不要把完整研究資料貼入委派；只傳來源索引與子任務邊界，讓每個 Agent局部讀取。

多 Agent總量 ≈ 協調輸入輸出
+ Σ（子 Agent輸入輸出 + 工具）
+ Handoff與最終統整
COMMON最小共享契約

目標、全域限制、輸出 Schema與截止條件

LOCAL分支專屬上下文

只給該 Agent需要的檔案與證據

ARTIFACT公共資料外置

按 ID與範圍讀取，不複製全文

TOTAL加總所有上下文

協調、子 Agent、工具與統整都算

04

WRITE A WORK PACKAGE

委派不是一句『研究這個』，也不是貼整份主提示

Work Package包含單一目標、範圍、可用資料與工具、禁止跨越範圍、交付 Schema、必要證據、停止條件與預算。子 Agent不需要知道整個專案故事，只需知道其結果如何被使用。

範圍要能驗收，例如『檢查 payment模組三個指定檔案，列出最多五個有證據的風險』，比『看看支付有沒有問題』更能避免擴張。若資料不足，回傳 missing與最小需求，不自行開啟無關研究。

目標：
範圍／不做：
可用資料與工具：
必要證據：
輸出：findings[], evidence[], gaps[], recommendation
停止：完成全部欄位或達預算
OBJECTIVE單一可驗收目標

說明結果用途，不講多餘故事

SCOPE明確邊界

檔案、資料源、時間與不做事項

OUTPUT固定 Handoff Schema

結論、證據、風險、缺口與建議

BUDGET呼叫與停止

最大工具、Token、時間與失敗契約

05

COMPRESS THE RETURN

子 Agent不應把完整探索 Transcript交回協調者

每個子 Agent回傳：status、結論、最多N個 Findings、每項證據定位、信心、風險、缺口、衝突與建議。完整日誌與草稿保存為 Artifact，協調者只在衝突或驗證時局部讀取。

統一 Schema讓協調者可去重、排序與合併，不必讀不同風格長文。若子 Agent沒有發現問題，也要回傳範圍、檢查方式與限制，避免協調者誤以為沒有執行。

STATUS完成程度

complete、partial、blocked與失敗

FINDINGS有限高價值結果

依影響排序，每項附證據

GAPS未涵蓋範圍

權限、資料、時間與未知

ARTIFACT完整過程外置

需要時按 ID讀取，不進主上下文

06

KEEP THE COORDINATOR LEAN

不要讓總管重做每個子 Agent的研究

協調者的責任是拆分、監控、處理衝突、合併與最終驗證，而不是逐份重跑工具。接收 Handoff後先依主題和證據去重，再標記一致、互補與衝突；只有衝突會影響結論時才深入原始 Artifact。

限制協調者可見工具，若它只需要讀 Handoff和執行最終測試，就不要暴露所有研究工具。合併規則先定義：相同證據合併、相反結論要求第三證據、未驗證推論不可升級為事實。

DEDUP合併相同發現

依證據 ID、檔案與主題去重

SYNTHESIZE組合互補結果

保留來源與每個分支的適用範圍

CONFLICT只深挖重要衝突

取得原始證據或有限第三檢查

VERIFY做一次整體驗收

不重做全部探索，只測最終交付

07

LIMIT CONCURRENCY

更多 Agent可能只是把同樣的模糊問題複製更多次

設定最大子 Agent數、每 Agent預算、總 Budget與最晚停止時間。先用2–4個乾淨分支驗證，不因為可平行就自動把每個小標題都開一個 Agent。小任務的委派與統整成本可能超過工作本身。

若分支執行中發現依賴或重疊，協調者應合併或取消尚未開始工作，而不是讓兩邊完成相同研究。監控每個分支的新證據率、重複率與回報大小，找出沒有創造增量價值的分工。

FAN-OUT最大並行數

由任務分支與總預算決定，不追求越多

LOCAL BUDGET每個 Agent上限

Token、工具、時間與輸出數

GLOBAL BUDGET所有分支總額

到頂停止低優先分支或降級

CANCEL消除重複

發現重疊就合併，不付完整雙份成本

08

PROVE THE ORCHESTRATION

比較 Token、時間、品質與重複率，不只看完成得更快

使用同一組可分任務跑 Single Agent與Multi-agent，記錄總輸入、總輸出、工具、牆鐘時間、成功率、證據完整性、重複研究、Handoff與統整成本。再按主要目標決定是否採用。

若多 Agent只在大型任務節省時間，就讓路由器只對達到分支門檻的任務啟用；小任務保持單 Agent。若品質提升但成本增加，明確將其定位為品質模式，而不是宣稱省 Token。

總量、時間、品質與失敗模式

MULTI所有分支加總

協調、複製、Handoff與統整

GAIN主要收益

時間、品質或Token三者分開報告

ROUTE只在門檻後啟用

依分支數、資料範圍與風險決定

BEFORE / AFTER

四個 Agent平行研究，為什麼總 Token變成3.6倍？

WASTEFUL

每個 Agent收到相同25k背景，任務邊界模糊，最後都查了相同三個來源。

OPTIMIZED

共享契約縮成1.2k；背景成 Artifact；各 Agent只拿分支索引；Handoff固定最多五項證據。

CHECK YOUR MODEL

先回答，再展開。

多 Agent最常節省的是什麼？

乾淨分支平行時主要節省牆鐘時間，不會自動節省總 Token。

哪些任務不適合平行？

後一步依賴前一步語意結果、共享寫入或分工邊界高度重疊的任務。

如何減少背景複製？

共享最小契約，分支只拿專屬內容，公共完整資料以 Artifact按需讀取。

協調者需要完整研究工具嗎？

通常不需要。它主要讀 Handoff、處理衝突與最終驗證。

什麼情況可說多 Agent省 Token？

所有 Agent、工具、Handoff與統整加總後，每成功任務總 Token仍較低且品質通過。

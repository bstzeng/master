Linked Lists

走訪與搜尋

沿著 next 前進，直到找到目標或走到終點

入門25 分鐘PYTHON 3

WHY THIS MATTERS

使用 current 指標走訪節點，轉換資料並搜尋第一個符合條件的位置。

LEARNING GOALS

  • 寫出不遺失 head 的走訪迴圈
  • 搜尋指定值並回傳節點
  • 分析走訪與搜尋的成本
01

current 是移動中的指標

走訪時通常保留 head 不動，另以 current 指向目前節點。每輪處理 current.value 後執行 current = current.next，直到 current 變成 None。

  • 文字圖：current → [10] → [20] → [30] → None
  • 前進一次後：head 仍指向 [10]，current 改指向 [20]
  • while current is not None 可同時處理最後一個節點
02

搜尋第一個符合的節點

搜尋時逐節點比較 value，找到後可立即回傳節點參照，走到 None 則代表不存在。回傳節點而不是只有布林值，能讓呼叫端繼續讀取或修改該節點。

  • 找到目標：return current
  • 走完整條鏈仍未找到：return None
  • 有重複值時，此版本回傳第一個符合節點
03

終止條件與複雜度

含 n 個節點的完整走訪耗時 O(n)，current 只是一個額外參照，所以額外空間是 O(1)。搜尋最好情況在 head 就找到，時間 O(1)；最壞情況則要走到尾端，時間 O(n)。

  • 忘記更新 current 會造成無限迴圈
  • 誤寫 while current.next 會漏掉最後一個節點
  • 空串列時 current 一開始就是 None，迴圈自然不執行
KEY IDEA

走訪骨架是多數鏈結串列演算法的起點，先確認何時處理節點、何時前進。

RECAP

這堂課要帶走的事

  1. 01保留 head，使用 current 沿 next 逐節點前進。
  2. 02搜尋可在找到第一個符合節點時提早回傳。
  3. 03完整走訪時間 O(n)，迭代寫法額外空間 O(1)。

CHECK YOURSELF

先想一想，再看答案

為什麼走訪常用 current，而不直接反覆修改 head？

current 能移動而保留串列入口；若覆寫唯一的 head 參照，之後可能無法再從開頭存取串列。

while current.next is not None 會漏掉什麼？

迴圈會在 current 位於最後一個節點時停止，因此最後一個節點不會被迴圈內容處理。

PRACTICE

延伸練習

  1. 寫一個 count_nodes 函式，回傳鏈結串列的節點數量。
  2. 寫一個 find_last 函式，回傳最後一個等於 target 的節點。

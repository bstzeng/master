Searching Algorithms

Linear Search 線性搜尋

按順序檢查資料，是最直接也最通用的搜尋方式

入門20 分鐘PYTHON 3

WHY THIS MATTERS

學會逐筆搜尋、處理找不到與重複值，並理解提前結束對最佳及最壞情況的影響。

LEARNING GOALS

  • 實作回傳索引的線性搜尋
  • 說明最佳、最壞與額外空間複雜度
  • 判斷線性搜尋適合的資料情境
01

逐筆檢查不需要排序

線性搜尋（Linear Search）從第一筆資料開始逐一比較，遇到目標就停止。它不要求資料已排序，也適用於只能依序讀取的資料，因此常是最可靠的第一版解法。

  • 輸入可以是未排序序列
  • 找到目標時可以提前 return
  • 找不到時必須掃描全部 n 筆
02

明確定義回傳契約

搜尋函式應事先約定找到與找不到時回傳什麼，也要說明重複值出現時回傳哪一個位置。下例回傳第一個相符索引，找不到則回傳 -1；這個契約讓呼叫端不必猜測。

  • enumerate 同時取得索引與元素
  • 第一個相符項目立刻結束
  • 空 list 自然得到 -1
03

複雜度與適用時機

目標在第一格時只比較一次，最佳情況是 O(1)；目標在最後或不存在時需要比較 n 次，最壞情況是 O(n)。若資料很小、只查一次或無法排序，線性搜尋常比建立額外索引更划算。

  • 最佳時間 O(1)
  • 最壞時間 O(n)
  • 額外空間 O(1)
  • 反覆查詢大型固定資料時可考慮排序或雜湊索引

  2. 02回傳值與重複值規則應寫入函式契約

CHECK YOURSELF

先想一想，再看答案

在未排序 list 中找一筆資料，能直接使用一般二分搜尋嗎？

不能。一般二分搜尋依賴排序來排除一半範圍；未排序時應先線性搜尋，或在值得時先建立適合的索引。

linear_search([4, 7, 4], 4) 回傳什麼？

回傳 0，因為函式遇到第一個相符值就立即回傳索引。

PRACTICE

延伸練習

  1. 改寫函式，使它回傳 target 出現的所有索引，並分析時間與輸出空間。
  2. 為線性搜尋設計空 list、重複值、第一格命中與找不到四種測試。

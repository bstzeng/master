Searching Algorithms

Binary Search on Answer 對答案二分搜尋

不直接找資料，而是在可行答案中找臨界值

中階30 分鐘PYTHON 3

WHY THIS MATTERS

辨認單調可行性，建立判斷函式，並用二分搜尋找到最小可行答案。

LEARNING GOALS

  • 辨認答案空間的單調性
  • 分離可行性判斷與邊界搜尋
  • 分析答案範圍帶來的對數成本
01

搜尋單調的真假分界

對答案二分搜尋（Binary Search on Answer）不是在陣列找 target，而是在一段候選答案中找最小可行或最大可行值。關鍵是可行性具有單調性，例如速度越快越能在期限內完成，真假排列才會形成可搜尋的分界。

  • 先定義候選答案的上下界
  • 設計 can_finish(answer) 判斷是否可行
  • 確認可行性只會從 False 轉 True，或反向一次
  • 沒有單調性就不能直接使用二分
02

範例：找最低處理速度

假設 tasks 記錄每批工作量，每小時以 speed 處理同一批，完成一批所需時間為向上取整 task/speed。若某速度能在 hours_limit 內完成，更高速度也一定可行，因此可搜尋第一個可行速度。

  • 最低候選速度為 1
  • 最高只需到 max(tasks)
  • 每次可行性檢查走訪全部 n 批工作
03

複雜度與正確性檢查

若候選答案範圍寬度為 R，二分最多檢查 O(log R) 次，而每次 can_finish 花 O(n)，總時間 O(n log R)、額外空間 O(1)。實作前還要驗證上下界涵蓋答案、至少存在一個可行值，並確認判斷函式沒有隱藏的非單調條件。

  • 總成本 = 判斷成本 × 二分輪數
  • 邊界答案本身不一定出現在輸入資料中
  • 以最小可行值測試 left - 1 不可行、left 可行
  • 不合法或無解輸入要由函式契約處理

RECAP

這堂課要帶走的事

  1. 01對答案二分搜尋需要單調的可行性分界
  2. 02把判斷函式與搜尋邊界分開能讓邏輯更易驗證
  3. 03總時間是一次可行性判斷成本乘上 O(log R)

CHECK YOURSELF

先想一想，再看答案

若 can_finish(10) 為 True，但 can_finish(11) 可能變成 False，可以直接找最小可行值嗎？

不能直接使用這個二分模板，因為可行性不具 False 到 True 的單調性，排除一半範圍的推論不成立。

候選範圍有一百萬個整數，二分大約需要幾十萬次判斷嗎？

不需要，只需約 log₂(1,000,000)，也就是約 20 次判斷。

PRACTICE

延伸練習

  1. 設計『在預算內能製作至少 k 件商品』的單調判斷，說明要找最大或最小哪種邊界。
  2. 替 minimum_speed 加入空 tasks、期限不足與單一工作批次的輸入檢查或測試。

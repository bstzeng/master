Searching Algorithms

BFS 廣度優先搜尋

按距離一層一層展開，找無權圖的最短路徑

中階32 分鐘PYTHON 3

WHY THIS MATTERS

使用佇列進行廣度優先搜尋，計算無權圖的最少邊數距離，並與 DFS 比較。

LEARNING GOALS

  • 解釋 BFS 的分層探索順序
  • 使用 deque 實作 BFS 距離計算
  • 比較 BFS 與 DFS 的搜尋特性
01

佇列維持由近到遠的順序

廣度優先搜尋（Breadth-First Search, BFS）先探索距離起點一條邊的所有頂點，再探索距離兩條邊的頂點。先進先出的佇列（Queue）維持這個分層順序，因此某個頂點第一次被發現時，就已得到無權圖中的最少邊數距離。

  • 佇列使用先進先出順序
  • 搜尋像水波一樣逐層向外擴散
  • 第一次發現即得到無權圖最短距離
  • 有不同邊權重時不能直接套用此結論
02

用 deque 實作距離搜尋

Python 應使用 collections.deque 的 popleft 進行 O(1) 出隊，不要使用 list.pop(0) 的 O(n) 搬移。將頂點加入 queue 時立刻記錄 distance，也就同時標示 visited，避免它被其他父節點重複排入。

  • distance dict 同時記錄已訪問與距離
  • 鄰居距離等於目前距離加 1
  • 可加入 parent dict 還原實際路徑
03

在 DFS 與 BFS 之間選擇

DFS 與 BFS 都能判斷可達性，使用鄰接表時也都是 O(V + E)，差別主要在探索順序與記憶體形態。要找無權最短路徑或層級時優先考慮 BFS；要深入探索、回溯或處理連通結構時 DFS 常更自然，但實際仍取決於問題。

  • BFS：無權最短路徑、層級、最少步數
  • DFS：深入探索、連通區塊、回溯結構
  • BFS 前線很寬時可能同時保存許多頂點
  • 兩者在一般圖中都需要 visited

CHECK YOURSELF

先想一想，再看答案

為什麼 BFS 應在入隊時而非出隊時標記 visited？

入隊時標記可避免同一頂點在真正出隊前被多個鄰居重複加入，減少重複工作並維持清楚的第一次發現距離。

道路每條有不同通行時間時，BFS 找到的邊數最少路徑一定耗時最短嗎？

不一定。BFS 只最小化邊數；有非負權重時通常要使用 Dijkstra 等加權最短路徑演算法。

Searching Algorithms

DFS 深度優先搜尋

沿著一條路深入到底，再回頭探索其他分支

中階30 分鐘PYTHON 3

WHY THIS MATTERS

把問題表示成圖，使用堆疊或遞迴進行深度優先搜尋，並以 visited 避免循環。

LEARNING GOALS

  • 解釋 DFS 的走訪順序與堆疊關係
  • 實作鄰接表圖的迭代 DFS
  • 分析 O(V + E) 時間與 O(V) 空間
01

搜尋策略不只用來找數字

深度優先搜尋（Depth-First Search, DFS）是一種探索狀態空間或圖的策略：先沿一個分支深入，無路可走後再回到最近的分岔。網頁連結、城市道路、迷宮位置或任務依賴都能表示成頂點與邊，再交給 DFS 探索。

  • 頂點（Vertex）代表狀態或物件
  • 邊（Edge）代表可到達或關聯
  • 堆疊的後進先出形成深入順序
  • 適合可達性、連通區塊與路徑存在問題
02

用 visited 避免重複探索

一般圖可能存在循環，例如 A 到 B、B 又回到 A；若不記錄已看過頂點，搜尋可能無限進行。下例在放入 stack 時就加入 visited，確保同一頂點最多排入一次。

  • stack 儲存待探索頂點
  • visited set 提供平均 O(1) 成員檢查
  • 鄰居反向放入可讓輸出更接近原鄰接順序
03

複雜度與遞迴版本

使用鄰接表時，每個可達頂點最多處理一次、每條邊最多檢查固定次數，所以時間 O(V + E)，visited 與 stack 最多容納 O(V)。遞迴 DFS 由呼叫堆疊代替顯式 stack，寫法簡潔，但很深的路徑可能超過 Python 遞迴深度。

  • V 是頂點數，E 是邊數
  • 時間 O(V + E)
  • 額外空間 O(V)
  • DFS 不保證無權圖的最少邊數路徑

CHECK YOURSELF

先想一想，再看答案

樹通常不回到父節點，為什麼一般圖的 DFS 仍需要 visited？

一般圖可能有循環或多條路徑通往同一頂點；visited 能防止無限循環並避免重複探索。

DFS 找到的第一條路徑一定是邊數最少的嗎？

不一定。DFS 會先深入某個分支；在無權圖中需要最少邊數路徑時通常使用 BFS。

PRACTICE

延伸練習

  1. 修改 dfs，使它收到 target 並回傳 target 是否可從 start 到達。
  2. 用遞迴實作同一個 DFS，並說明呼叫堆疊的最壞深度。

UNIT 12 / LESSON 03

Greedy Algorithms

區間合併

排序後只需和目前合併區間比較

中階27 分鐘PYTHON 3

WHY THIS MATTERS

將重疊區間合併成互斥結果，理解排序如何把全域關係轉成局部決策。

LEARNING GOALS

  • 定義區間重疊規則
  • 實作排序後線性合併
  • 說明不變量與複雜度
01

排序讓可能重疊者相鄰

區間合併要把所有相交區間合成覆蓋相同範圍的互不重疊區間。按 start 升冪後，若下一段連目前合併區間都接不上，它也不可能和更早已完成的區間重疊，因此只需比較結果尾端。

  • 先定義端點接觸是否算重疊
  • 排序鍵使用 start
  • 結果始終保持有序且互不重疊
02

重疊就延伸，分離就封存

若 start <= merged[-1][1]，兩區間重疊，將尾端 end 更新為兩者最大值；否則加入新的獨立區間。下例複製每個區間，避免修改呼叫端原有的內層 list。

  • 空輸入直接回傳空結果
  • 重疊時不新增結果數量
  • 分離時上一段已不會再被後續改變
03

不變量保證沒有漏合併

每輪開始時，merged 已正確合併所有處理過的區間，且尾端是唯一仍可能與下一區間重疊者。依 start 排序使更早結果的 end 不可能跨過尾端而單獨碰到下一段，因此局部比較足夠維持不變量。

  • 排序成本 O(n log n) 主導
  • 掃描本身 O(n)
  • 若輸入已按 start 排序可降為 O(n)
  • 半開區間若端點接觸不算重疊，條件改用 start < end

RECAP

這堂課要帶走的事

  1. 01依開始時間排序後，只需比較目前結果尾端
  2. 02每輪選擇是延伸尾端或封存後新增
  3. 03總時間 O(n log n)，已排序輸入可 O(n) 掃描

CHECK YOURSELF

先想一想，再看答案

為什麼合併時新 end 要取 max(current_end, end)？

下一區間可能完全被目前區間包含；直接指定 end 反而可能縮短已覆蓋範圍。

若區間是半開 [start,end)，[1,3) 與 [3,5) 是否重疊？

不重疊；此規格下應用 start < current_end 判斷，而不是 <=。

PRACTICE

延伸練習

  1. 手動合併 [(8,10),(1,4),(2,3),(9,12)]，記錄每輪 merged。
  2. 擴充程式，先驗證每個區間 start <= end，不合法時拋出例外。

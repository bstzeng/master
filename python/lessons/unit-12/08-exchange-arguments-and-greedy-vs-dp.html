UNIT 12 / LESSON 08

Greedy Algorithms

交換論證與 Greedy vs DP

用證明與狀態需求決定是否能放心不回頭

中階35 分鐘PYTHON 3

WHY THIS MATTERS

整理交換論證模板，比較貪心與動態規劃，建立面對陌生最佳化問題的決策流程。

LEARNING GOALS

  • 寫出交換論證骨架
  • 辨認 Greedy 與 DP 的狀態差異
  • 根據反例與證明選擇方法
01

交換論證把最佳解拉向貪心解

交換論證先取一個最佳解 O，找出它和貪心解 G 的第一個不同選擇，再證明能把 O 的選擇換成 G 的選擇而不破壞可行性、也不讓目標變差。反覆交換後得到包含所有貪心選擇的最佳解，便證明 G 也是最佳。

  • 先明確定義任意最佳解 O
  • 找第一個分歧位置
  • 證明交換後仍可行且不變差
  • 對剩餘子問題重複推論
02

Greedy 只保留一條路，DP 保留必要狀態

Greedy 認為某個局部選擇安全，因此丟棄其他候選，通常更快且空間較少；Dynamic Programming（DP）在無法安全丟棄時，依狀態保留多個子問題最佳值。是否存在重疊子問題不是貪心證明，關鍵仍是其他選擇能否被安全支配。

  • Greedy：不可撤銷地保留單一方向
  • DP：保存多個狀態以比較未來組合
  • 能證明安全選擇時優先 Greedy
  • 局部選擇互相影響且無交換性時考慮 DP
問題典型方法關鍵理由
最多不重疊活動Greedy最早結束可安全交換
分數背包Greedy物品可做等重量交換
0/1 背包DP不可切分使局部密度不安全
一般最少硬幣DP最大面額優先可能有反例
03

陌生問題的決策清單

先寫暴力或小型窮舉當作答案對照，再提出能排除候選的貪心規則；若找到反例，就識別必須保存哪些資訊形成 DP 狀態。若交換論證成功，仍要分析排序、Heap 或資料結構成本，而不是只看最後一趟掃描。

  • 用小輸入驗證候選規則
  • 說出選擇後被永久丟棄的方案
  • 嘗試交換、領先或不變量證明
  • 記錄時間、空間與輸入前提

RECAP

這堂課要帶走的事

  2. 02Greedy 丟棄替代路徑，DP 則保存足以比較未來的狀態

CHECK YOURSELF

先想一想，再看答案

交換論證只證明交換後仍可行，是否已足夠？

不足，還必須證明目標值不會變差，才能保證交換後仍是最佳解。

什麼跡象表示可能需要 DP 而非 Greedy？

局部最好選擇會影響後續組合、找得到反例，且無法安全丟棄其他候選時，通常需用狀態保存多種可能。

PRACTICE

延伸練習

  1. 為活動選擇寫出完整四步交換論證，不只描述直覺。
  2. 選一題最佳化問題，列出 Greedy 會丟棄的資訊與 DP 可能需要保存的狀態。

Greedy Algorithms

Huffman Coding

反覆合併最低頻率，建立最短加權前綴碼

中階35 分鐘PYTHON 3

WHY THIS MATTERS

使用最小堆建立 Huffman Tree，理解前綴碼、加權路徑長度與貪心合併。

LEARNING GOALS

  • 說明前綴碼與頻率目標
  • 以 heapq 建立 Huffman Tree
  • 理解最低頻率合併的正確性直覺
01

高頻符號應使用短碼

Huffman Coding 要為每個符號建立無歧義的二進位前綴碼，使頻率乘碼長的總和最小。前綴碼要求任何完整碼都不是另一碼的前綴，因此從編碼樹根沿 0、1 邊走到葉節點即可唯一解碼。

  • 符號放在葉節點
  • 左、右邊可分別標示 0、1
  • 目標是最小化加權碼長
  • 編碼形狀可能不唯一但最佳成本相同
02

最小堆反覆取兩個最低頻率

把每個符號當成單節點樹放入最小堆，每次取出頻率最低的兩棵樹，合成頻率總和的新樹再放回，直到只剩根。counter 用來在頻率相同時提供可比較的第二欄，避免 Python 比較節點物件。

  • 初始化 heapify 為 O(n)
  • 執行 n - 1 次合併
  • 每次 pop 與 push 為 O(log n)
  • 總時間 O(n log n)、樹空間 O(n)
03

最低頻率可成為最深兄弟

在某個最佳前綴碼樹中，可以把最低頻率的兩個符號安排為最深的一對兄弟而不增加成本；合併它們後，問題縮成少一個符號的同型問題。這提供貪心選擇與最佳子結構，展開合併節點便得到原問題最佳樹。

  • 低頻符號承擔較長路徑較便宜
  • 兄弟合併把共同前綴視為一個新符號
  • 交換只會讓加權成本不增
  • Huffman 最佳化碼長，不包含檔頭等實務開銷

CHECK YOURSELF

先想一想，再看答案

為什麼高頻符號通常應靠近根？

靠近根代表碼較短，高頻率乘上較短長度能降低總加權碼長。

建樹時為何使用最小堆而不是每輪重新排序？

最小堆可用 O(log n) 取出與放回極小值，使總時間 O(n log n)，避免反覆完整排序的額外成本。

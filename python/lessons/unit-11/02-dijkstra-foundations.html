Classic Graph Algorithms

Dijkstra：以最小暫定距離擴張

先理解貪心正確性與 O(V²) 版本

基礎35 分鐘PYTHON 3

WHY THIS MATTERS

理解 Dijkstra 的貪心選擇、鬆弛操作與非負權重限制，實作簡單版本。

LEARNING GOALS

  • 解釋 Dijkstra 每輪選擇的頂點
  • 使用 Relaxation 更新距離
  • 實作並分析 O(V² + E) 版本
01

固定最近的未處理頂點

Dijkstra 每輪從尚未固定的頂點中，選出暫定距離最小者 u；當所有邊權皆非負時，未來繞路不可能讓 u 更短，因此可把它的距離固定。接著從 u 嘗試改善所有鄰居，逐步向外擴張已確定區域。

  • distance[start] = 0，其餘為無限大
  • 每輪選最小未拜訪頂點
  • 固定後不再改變其最短距離
  • 負邊會破壞固定距離的推論
02

Relaxation 鬆弛操作

鬆弛（Relaxation）檢查經過 u 到鄰居 v 是否比已知路線更短：若 distance[u] + weight < distance[v]，就更新 distance[v] 與 predecessor[v]。同一條邊可能被檢查，但只有真正變短時才更新。

  • candidate = distance[u] + weight
  • 只在 candidate 更小時更新
  • 更新 predecessor[v] = u 以便重建
  • 不可達頂點維持無限大
03

O(V²) 實作與限制

不使用 Heap 時，每輪線性掃描所有未拜訪頂點找最小值，共需 O(V²)，再加上走訪鄰接邊 O(E)，空間為 O(V + E)。這個版本容易理解，且在鄰接矩陣或非常稠密的圖上未必差，但仍禁止負權重。

  • 時間：O(V² + E)，通常寫作 O(V²)
  • 空間：圖加距離表為 O(V + E)
  • 可在取出目標頂點時提前停止
  • 遇到最小距離仍為無限大，表示剩餘頂點不可達
KEY IDEA

Dijkstra 的非負限制是正確性前提，不是單純的效能建議。

CHECK YOURSELF

先想一想，再看答案

Dijkstra 為何能固定目前距離最小的頂點？

所有邊權非負時，經過任何尚未固定頂點再繞回來都不會產生更小成本。

Relaxation 沒有改善距離時，是否要更新 predecessor？

不需要；predecessor 必須對應目前最短的已知路徑，只有距離變短時才一起更新。

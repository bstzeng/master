UNIT 11 / LESSON 08

Classic Graph Algorithms

Kruskal、Union-Find 與總比較

按邊排序、避免循環並完成選型

進階45 分鐘PYTHON 3

WHY THIS MATTERS

以 Union-Find 判斷安全邊並實作 Kruskal，最後比較本單元所有最短路徑與 MST 演算法。

LEARNING GOALS

  • 使用 Union-Find 維護連通分量
  • 實作 Kruskal 並分析 O(E log E)
  • 依問題條件完成演算法總選型
01

由最輕邊合併分量

Kruskal 將所有無向邊依權重由小到大排序，若某邊兩端位於不同連通分量，就接受它並合併分量；若已在同一分量，加入會形成循環，因此跳過。收集 V - 1 條邊即可提早停止。

  • 全域排序所有邊
  • 不同分量的最輕邊是安全邊
  • 同分量邊會形成循環
  • 不連通時得到 Minimum Spanning Forest
02

Union-Find 與完整實作

Disjoint Set Union（DSU／Union-Find）以 find 找代表、union 合併集合；路徑壓縮與按大小合併讓單次操作攤銷接近 O(1)，精確為 O(α(V))。Kruskal 的主成本來自排序，因此總時間 O(E log E)，額外空間 O(V)。

  • find(u) == find(v) 表示加入會成環
  • Path Compression 壓平查找路徑
  • Union by Size 將小樹接到大樹
  • 排序主導總時間 O(E log E)
03

經典圖論演算法總選型

先分清目標是路徑距離還是整體連線成本，再依負邊、查詢範圍與圖表示選擇演算法。Kruskal 適合已有邊列表或稀疏圖，Prim 適合鄰接表與連續擴張；Dijkstra、Bellman–Ford、Floyd–Warshall 則回答不同條件下的最短路徑。

  • 單源非負：Heap Dijkstra
  • 單源含負邊或需負環檢測：Bellman–Ford
  • 全點對且 V 不大：Floyd–Warshall
  • MST：鄰接表偏 Prim，邊列表偏 Kruskal
演算法問題時間條件與限制
Dijkstra + Heap單源最短路徑O((V+E) log V)不可有負邊
Bellman–Ford單源最短路徑O(VE)可負邊、可測可達負環
Floyd–Warshall全點對最短路徑O(V³)O(V²) 空間，可測負環
Prim + HeapMSTO(E log V)無向連通、鄰接表
Kruskal + DSUMSTO(E log E)無向圖、邊列表
KEY IDEA

若題目條件不滿足演算法前提，跑出數字也不代表答案正確；選型檢查必須先於實作。

CHECK YOURSELF

先想一想，再看答案

Kruskal 為何需要 Union-Find？

它要快速判斷邊兩端是否已在同一連通分量；若是，加入該邊就會形成循環。

一張大型稀疏非負圖只問單一起點距離，應選 Floyd–Warshall 嗎？

通常不選；Heap Dijkstra 的 O((V+E) log V) 更符合單源與稀疏條件，Floyd–Warshall 會做 O(V³) 的全點對計算。

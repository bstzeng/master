Classic Graph Algorithms

Heap 優化 Dijkstra

在稀疏圖上有效率地取得最近頂點

進階40 分鐘PYTHON 3

WHY THIS MATTERS

以 heapq 取代線性選最小值，使用延遲刪除處理過期項目，完成常用 Dijkstra 模板。

LEARNING GOALS

  • 以 Min Heap 保存暫定距離與頂點
  • 正確忽略過期的 Heap 項目
  • 分析 O((V + E) log V) 複雜度
01

Min Heap 取代線性搜尋

把 (distance, vertex) 放入 Min Heap，就能以 O(log V) 取得目前暫定距離最小的候選，而非每輪掃描 O(V)。每次鬆弛成功就推入新距離，特別適合 E 遠小於 V² 的稀疏圖。

  • Heap 根是最小暫定距離
  • 起點項目為 (0, start)
  • 鬆弛成功才 heappush
  • 頂點若不可互相比較，可加入序號 tie-breaker
02

過期項目與延遲刪除

heapq 不提供有效率的 decrease-key，所以某頂點距離改善時直接推入新項目，舊項目留到取出時再判斷。若 popped_distance 不等於目前 distance[vertex]，它就是過期候選，可直接 continue。

  • 同一頂點可能同時有多筆 Heap 項目
  • distance 字典保存唯一最新答案
  • 過期項目不展開鄰居
  • 這種策略稱為 Lazy Deletion（延遲刪除）
03

完整模板與複雜度

使用鄰接表與二元 Heap 時，每條邊最多觸發一次成功更新並付出對數成本，常寫為 O((V + E) log V) 或 O(E log V)，空間 O(V + E)。負邊仍然禁止；若只查單一終點，可在該終點以最新距離彈出時提早停止。

  • 適用：非負權重的稀疏圖
  • 時間：O((V + E) log V)
  • 空間：O(V + E)，Heap 可能含過期項目
  • 終點第一次以有效距離 pop 時已確定最短
版本選最小值總時間較適合
線性掃描O(V)O(V² + E)稠密圖或教學
二元 HeapO(log V)O((V + E) log V)稀疏圖

RECAP

這堂課要帶走的事

  1. 01Min Heap 將取得最小暫定距離的成本降為對數時間
  2. 02距離改善時推入新項目，取出後以 distance 判斷並忽略過期項目
  3. 03Heap Dijkstra 適用非負稀疏圖，時間為 O((V + E) log V)

CHECK YOURSELF

先想一想，再看答案

為何距離改善時不必從 Heap 中搜尋並刪除舊項目？

可直接推入新項目，舊項目取出時以最新 distance 判斷為過期並忽略，避免 O(n) 搜尋。

何時能安全地對單一 target 提早停止？

target 以等於 distance[target] 的有效距離從 Heap 彈出時，其最短距離已固定。

PRACTICE

延伸練習

  1. 將 O(V²) Dijkstra 改寫為 heapq 版本並比較兩者輸出。
  2. 在模板中加入 target 與路徑重建，回傳最短成本及完整路線。

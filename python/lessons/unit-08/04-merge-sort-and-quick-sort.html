Recursion, Divide and Conquer, and Backtracking

Merge Sort 與 Quick Sort 分治案例

比較先切後合併與先分割後遞迴

基礎35 分鐘PYTHON 3

WHY THIS MATTERS

以兩種經典排序比較分治步驟、複雜度與資料分割品質。

LEARNING GOALS

  • 說明 Merge Sort 的合併流程
  • 說明 Quick Sort 的 pivot 分割
  • 比較兩者時間與空間特性
01

Merge Sort：先排兩半再合併

合併排序（Merge Sort）把陣列切半，遞迴排序左右兩半，再用雙指標線性合併。Base Case 是長度小於等於一，因為這樣的陣列已經有序。

  • Divide：以 middle 切成兩半
  • Conquer：遞迴排序 left 與 right
  • Combine：每次取兩側目前較小值
02

Quick Sort：pivot 決定分割

快速排序（Quick Sort）選一個 pivot，把其餘元素分成小於等於與大於 pivot 的兩側，再遞迴排序。分割若大致平衡會有良好表現，若每次都極度不平衡，遞迴深度可能增長到 n。

  • Partition 是 Quick Sort 的核心工作
  • pivot 選擇影響分割是否平衡
  • 下列教學版建立新陣列，易讀但不是原地排序
03

複雜度比較

Merge Sort 無論輸入順序，時間都是 O(n log n)，但合併通常需 O(n) 額外空間。Quick Sort 平均 O(n log n)、最壞 O(n²)；教學版也使用 O(n) 級新陣列，而原地版本主要使用遞迴堆疊。

  • Merge Sort 的合併穩定且分割固定平衡
  • Quick Sort 的效能取決於 pivot 與分割品質
  • 同名演算法的不同實作可能有不同空間成本

CHECK YOURSELF

先想一想，再看答案

Merge Sort 為什麼能保證 O(n log n) 時間？

每次固定切半形成約 log n 層，而每層合併所有元素的總工作量是 O(n)。

Quick Sort 何時可能退化成 O(n²)？

當 pivot 反覆造成極不平衡分割，例如一側接近 n-1、另一側接近 0 時，會有約 n 層且每層做線性分割。

PRACTICE

延伸練習

  1. 逐步合併 [2, 7] 與 [1, 5, 8]，記錄兩個指標的位置。
  2. 為 quick_sort 改用隨機 pivot，並說明它改善的是預期表現而非最壞上界。

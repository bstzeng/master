UNIT 08 / LESSON 01

Recursion, Divide and Conquer, and Backtracking

遞迴結構、Base Case 與 Call Stack

讓函式處理較小版本的同一問題

入門25 分鐘PYTHON 3

WHY THIS MATTERS

認識遞迴問題、終止條件與呼叫堆疊，並以階乘建立基本結構。

LEARNING GOALS

  • 辨認遞迴案例與 Base Case
  • 說明問題規模如何縮小
  • 理解 Call Stack 保存的執行狀態
01

遞迴的兩個必要部分

遞迴（Recursion）讓函式呼叫自己，去處理規模更小但形式相同的問題。每個遞迴函式都要有直接回答的終止條件（Base Case），以及確實朝終止條件前進的遞迴案例。

  • Base Case：不再呼叫自己，直接回傳
  • Recursive Case：把問題縮小後再次呼叫
  • 若規模沒有縮小，可能無限遞迴
02

Call Stack 保存尚未完成的工作

函式每次呼叫自己，Python 都會在呼叫堆疊（Call Stack）新增一個框架，保存參數與尚未執行的乘法。到達 Base Case 後，框架才由最深層開始依相反順序回傳。

  • 向下呼叫：factorial(3) 等待 3 × factorial(2)
  • 最深層：factorial(1) 直接回傳 1
  • 向上回傳：1 → 2 × 1 → 3 × 2
03

終止、深度與限制

factorial(n) 共有約 n 層呼叫，因此時間 O(n)，Call Stack 額外空間也是 O(n)。Python 有遞迴深度限制，所以非常深的線性遞迴通常適合改寫成迴圈。

  • 遞迴深度是同時存在的堆疊框架數
  • Base Case 正確不代表輸入一定能到達它
  • 選擇遞迴前要同時評估可讀性與堆疊空間
KEY IDEA

遞迴不是自動更快；它主要讓具有自我相似結構的解法更容易表達。

RECAP

這堂課要帶走的事

  1. 01遞迴必須有 Base Case，且每次呼叫都要縮小問題。
  2. 02Call Stack 保存尚未完成的函式狀態，並以後進先出順序返回。
  3. 03線性遞迴常同時需要 O(n) 時間與 O(n) 堆疊空間。

CHECK YOURSELF

先想一想，再看答案

只有 Base Case，為什麼遞迴函式仍可能不終止？

若遞迴參數沒有朝 Base Case 前進，例如數值反而愈來愈大，就永遠無法到達終止條件。

factorial(5) 的 Call Stack 額外空間為什麼是 O(n)？

最深時需同時保留從 factorial(5) 到 Base Case 的約 n 個呼叫框架。

PRACTICE

延伸練習

  1. 用遞迴計算 1 到 n 的總和，並處理 n=0。
  2. 預測 countdown(3) 的完整輸出順序，再實際執行核對。

UNIT 08 / LESSON 02

Recursion, Divide and Conquer, and Backtracking

遞迴追蹤與複雜度

用遞迴樹分清呼叫次數與最大深度

基礎30 分鐘PYTHON 3

WHY THIS MATTERS

以二元字串和 Fibonacci 比較分支遞迴的時間、堆疊深度與重複子問題。

LEARNING GOALS

  • 手動追蹤分支遞迴
  • 區分遞迴樹節點數與高度
  • 辨認重複子問題造成的浪費
01

先畫參數，再畫分支

追蹤遞迴時，把每次函式呼叫畫成節點，子呼叫畫成下一層分支。節點總數近似總工作量，從根到最深葉節點的距離則近似同時占用的 Call Stack 深度。

  • 一個呼叫只產生一個子呼叫：通常是鏈狀
  • 一個呼叫產生兩個子呼叫：可能形成二元樹
  • 時間看所有節點，堆疊空間看單一路徑高度
02

分支數決定成長速度

長度 n 的二元字串共有 2ⁿ 個輸出，因此演算法至少要花 O(2ⁿ) 時間產生它們，最大遞迴深度是 O(n)。回傳的所有字串需大量輸出空間，但若只分析執行堆疊，額外空間仍是 O(n)。

  • 第 0 層 1 個呼叫，第 1 層 2 個，第 n 層 2ⁿ 個
  • 輸出本身指數成長時，演算法無法是多項式時間
  • 分析空間時應註明是否包含回傳結果
觀察對象二元分支結果
呼叫總數O(2ⁿ)
最大堆疊深度O(n)
輸出數量2ⁿ 個
03

重複子問題的警訊

樸素 Fibonacci 會反覆計算相同的 fib(k)，例如 fib(5) 的左右分支都可能再次呼叫 fib(3)。它的時間呈指數成長、堆疊深度 O(n)；之後可用記憶化或動態規劃保存答案。

  • 相同參數反覆出現在遞迴樹中，就是重複子問題
  • 樸素 fib(n) 時間約 O(2ⁿ)
  • 不是所有分支遞迴都能或需要用記憶化

RECAP

這堂課要帶走的事

  1. 01遞迴樹節點總數對應時間，樹高對應 Call Stack 空間。
  2. 02每層固定二元分支且深度 n 時，呼叫數可能是 O(2ⁿ)。
  3. 03相同參數重複出現，是考慮記憶化的訊號。

CHECK YOURSELF

先想一想，再看答案

為什麼二元分支遞迴有 O(2ⁿ) 呼叫，Call Stack 卻不是 O(2ⁿ)？

分支會依序執行，堆疊同時只保留一條根到葉的路徑，所以最大深度是 O(n)。

看見兩個遞迴呼叫就一定能斷定時間 O(2ⁿ) 嗎？

不能，還要看子問題規模、是否有重疊、是否提早終止，以及每個節點本身的工作量。

PRACTICE

延伸練習

  1. 畫出 fibonacci(5) 的遞迴樹，圈出重複出現的參數。
  2. 分析遞迴二分搜尋的呼叫數、最大深度與額外空間。

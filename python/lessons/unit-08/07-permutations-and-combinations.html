Recursion, Divide and Conquer, and Backtracking

排列與組合

分清順序是否重要，再選擇 used 或 start

基礎35 分鐘PYTHON 3

WHY THIS MATTERS

比較排列與組合的狀態設計，並用剩餘數量剪去不可能的組合分支。

LEARNING GOALS

  • 區分排列與組合
  • 以 used 追蹤排列中已選索引
  • 以 start 產生固定長度組合
01

排列：順序不同就是不同答案

排列（Permutation）中 [1, 2] 與 [2, 1] 是不同答案，因此每一層都要考慮所有尚未使用的元素。used[index] 記錄某個輸入位置是否已在目前 path 中，防止同一位置重複使用。

  • 完成條件：len(path) == len(numbers)
  • 選擇後設 used[index] = True
  • 撤銷時 pop 並恢復 used[index] = False
02

組合：只保留選了哪些元素

組合（Combination）不區分選取順序，所以選擇下一個元素時只向右走，避免把相同集合以不同順序重複產生。當 path 長度到達 k，就記錄答案並返回。

  • start 限制下一個可選的最小索引
  • 選 index 後，下一層從 index + 1 開始
  • [1, 2] 會產生，但不再產生 [2, 1]
03

複雜度與剩餘數量剪枝

互異元素的全排列有 n! 個輸出，複製每個答案後時間可寫成 O(n·n!)；k 組合有 C(n,k) 個輸出，產生結果至少需 O(k·C(n,k))。組合搜尋時若剩餘元素不足以填滿 k，就可提早停止迴圈。

  • still_needed = k - len(path)
  • 迴圈最大起點可限制為 len(numbers) - still_needed
  • 排列與組合的遞迴工作空間分別最多 O(n) 與 O(k)

RECAP

這堂課要帶走的事

  1. 01排列在意順序，常用 used；組合不在意順序，常用 start。
  2. 02回溯狀態必須區分輸入位置，尤其當值可能重複時。
  3. 03安全剪枝必須能證明被略過的分支不可能完成答案。

CHECK YOURSELF

先想一想，再看答案

為什麼組合使用 start 後不會產生 [2, 1]？

選取索引 2 後只能繼續考慮更右側索引，不能回到索引 1，因此每組元素只依索引遞增順序出現。

全排列的時間為什麼不能低於答案數量 n! 的量級？

演算法必須至少輸出 n! 個不同排列，而每個輸出本身還包含 n 個元素。

PRACTICE

延伸練習

  1. 產生長度為 k 的排列，也就是從 n 個元素選 k 個且順序重要。
  2. 讓排列函式處理含重複值的輸入，使用排序與同層去重避免重複答案。

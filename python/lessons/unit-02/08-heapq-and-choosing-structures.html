UNIT 02 / LESSON 08

Python Built-in Data Structures

heapq 與資料結構選型

維護最高優先項目並完成整體比較

入門30 分鐘PYTHON 3

WHY THIS MATTERS

使用 heapq 建立最小堆積與優先佇列，並以操作成本與資料語意完成容器選型。

LEARNING GOALS

  • 使用 heappush、heappop 與 heapify
  • 解釋 Heap 與排序 List 的差異
  • 用決策表為實際問題選擇容器
01

最小堆積與優先佇列

Heap（堆積）讓最小元素保持在索引 0，適合每次取出目前最高優先權項目，而不必維持全部資料有序。Python 的 heapq 操作一般 List，heappush 與 heappop 都是 O(log n)，查看 heap[0] 是 O(1)。

  • heapq 預設是 Min Heap（最小堆積）
  • heappush：加入並維持堆積，O(log n)
  • heappop：取出最小項目，O(log n)
  • 堆積陣列不是完整排序結果
02

建堆、最大堆與 Top K

heapify 能在 O(n) 時間把現有 List 轉成堆積，比逐一加入的 O(n log n) 更適合批次資料。需要最大優先值時可依 Python 版本使用最大堆 API，或在相容寫法中存負數；維護大小為 k 的 Heap 可在 O(n log k) 找出 Top K。

  • heapq.heapify(items)：O(n)
  • 反轉數值正負可模擬 Max Heap
  • heapreplace／heappushpop 可合併替換步驟
  • 全部排序通常 O(n log n)，只取 Top K 可用 O(n log k)
03

用操作需求完成選型

選資料結構時，不只比較 Big O，也要看資料語意、可讀性與最常發生的操作。先選最直接表達需求的結構，再以實際輸入規模檢查瓶頸；若需要完整有序結果就排序，若只反覆取得最小值才使用 Heap。

  • 順序與索引：List／Tuple／String
  • 鍵值查找：Dictionary；唯一成員：Set
  • 兩端進出：deque；反覆取最小優先：Heap
  • 複雜度相同時，選語意更清楚、介面更簡單者
結構最適合核心成本
List動態有序資料、索引索引 O(1)，中間增刪 O(n)
Tuple固定紀錄、複合鍵索引 O(1)，不可變
Dictionary鍵到值的對應查找／更新平均 O(1)
Set唯一性、成員測試查找／加入平均 O(1)
String不可變文字走訪 O(n)，大量串接用 join
dequeQueue 與雙端操作兩端增刪 O(1)
Heap動態最小值、優先佇列查看 O(1)，增刪 O(log n)
KEY IDEA

Heap 只保證根節點最小，不保證直接走訪時由小到大。

RECAP

這堂課要帶走的事

  1. 01heapq 以 O(log n) 加入或取出最小項目，查看最小值為 O(1)
  2. 02只需 Top K 或動態優先項目時，Heap 通常比反覆完整排序合適
  3. 03選型同時考慮資料語意、常用操作、複雜度與可讀性

CHECK YOURSELF

先想一想，再看答案

直接印出 Heap 內部 List，會得到完整排序嗎？

不會；Heap 只維持父節點不大於子節點等局部規則，僅能保證索引 0 是最小值。

任務會持續加入，且每次都要取出最小期限，該選排序 List 還是 Heap？

選 Heap；每次加入與取出為 O(log n)，不必在每次更新後重新維持完整排序。

PRACTICE

延伸練習

  1. 使用 heapq 依照截止時間處理五項任務，若時間相同再依名稱排序。
  2. 為通訊錄、瀏覽紀錄、待辦優先權與不重複關鍵字各選資料結構並分析主要操作成本。

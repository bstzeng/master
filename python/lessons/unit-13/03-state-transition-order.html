UNIT 13 / LESSON 03

Dynamic Programming

State、Transition、Base Case 與順序

用四個問題設計 DP

基礎30 分鐘PYTHON 3

WHY THIS MATTERS

建立可重複使用的 DP 設計流程。

LEARNING GOALS

  • 精確定義 state
  • 列出 transition 與 base case
  • 決定合法計算順序
01

先定義 State

State 必須用一句可驗證的話描述，例如 dp[i] 是處理前 i 個元素的最佳值。索引範圍與答案位置也應同時寫清楚。

  • 狀態要包含影響未來的資訊
  • 避免讓 dp[i] 同時有兩種意思
KEY IDEA

若無法清楚說明 dp[i]，通常還不能開始寫程式。

02

最後一步推導 Transition

問答案最後一步可能做了什麼，再把各選擇連到較小狀態。Base Case 提供最小問題答案，也必須涵蓋空輸入。

  • 取最大、最小或加總取決於題意
  • 檢查每個轉移索引是否合法
  • 不可能狀態可初始化為 inf 或 False
設計項問題
Statedp[...] 代表什麼？
Transition最後一步有哪些選擇？
Base最小問題答案？
03

依賴決定順序

表格填寫時，依賴狀態必須先完成；若 dp[i] 依賴較小 i，就由左到右。二維 DP 則要同時檢查列與欄的方向。

  • 畫依賴箭頭可檢查順序
  • 空間壓縮可能改變內層迴圈方向
  • 答案不一定是 dp[-1]

RECAP

這堂課要帶走的事

  1. 01State 定義要包含索引範圍與語意。
  2. 02Transition 可由最後一步的所有選擇推導。
  3. 03計算順序必須符合依賴方向。

CHECK YOURSELF

先想一想，再看答案

為何不可能狀態常用 infinity？

做最小化時它不會錯誤成為較佳候選。

一維壓縮後迴圈方向可能改變嗎？

會；方向決定本輪讀到舊狀態或已更新的新狀態。

PRACTICE

延伸練習

  1. 為爬樓梯寫出 state、transition、base 與順序。
  2. 找一個答案不位於 dp[-1] 的例子並說明。

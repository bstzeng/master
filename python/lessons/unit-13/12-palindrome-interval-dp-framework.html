Dynamic Programming

回文、Interval DP 與統一解題框架

以區間長度安排依賴

進階45 分鐘PYTHON 3

WHY THIS MATTERS

用回文子序列介紹區間 DP，最後整理完整設計與驗證流程。

LEARNING GOALS

  • 定義區間狀態
  • 依區間長度填表
  • 套用 DP 統一框架
01

Longest Palindromic Subsequence

dp[left][right] 是閉區間內最長回文子序列長度。兩端相同就包住內區間加二，否則捨棄其中一端取最大。

  • 單字元區間 Base Case 為 1
  • 依區間長度由短到長
  • 時間與空間 O(n²)
02

Interval DP

區間 DP 以 [left,right] 為狀態，常枚舉分割點或比較兩端選擇。計算順序通常是區間長度遞增，因轉移依賴更短區間。

  • State：某區間的最佳值或方案數
  • Transition：端點決策或 split
  • 常見成本 O(n²) 狀態乘 O(n) 分割，即 O(n³)
步驟檢查
區間閉區間或半開區間？
Base空區間／單點？
順序短區間是否先完成？
03

DP 統一解題框架

先寫暴力選擇，再依重複參數定義 state；接著列 transition、base、順序與答案位置，最後才做空間優化。用小輸入手算表格並檢查空、單一、不可達與極端案例。

  • 1 定義狀態與索引範圍；2 寫轉移與 Base
  • 3 決定順序與答案；4 算狀態數×轉移成本
  • 5 驗證後才壓縮空間或重建路徑
KEY IDEA

空間優化是最後一步；先保留清楚表格以驗證正確性。

RECAP

這堂課要帶走的事

  1. 01區間 DP 常依更短區間，應按長度填表。
  2. 02狀態數乘每狀態轉移成本可估算時間。
  3. 03統一框架是 state、transition、base、order、answer、complexity。

CHECK YOURSELF

先想一想，再看答案

區間 DP 為何不能任意由 left 小到大、right 小到大？

該順序可能在內區間尚未完成前就讀取它；應依實際依賴安排。

DP 何時做空間優化較安全？

完整狀態與轉移已驗證正確，且確認未來只依賴有限舊狀態後。

PRACTICE

延伸練習

  1. 實作最長回文子字串的布林區間 DP。
  2. 挑一題依框架完整寫出 state、transition、base、order、answer 與複雜度。

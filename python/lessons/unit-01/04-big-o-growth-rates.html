Algorithm Foundations

Big O 與常見成長等級

忽略次要細節，專注輸入變大後的趨勢

入門25 分鐘PYTHON 3

WHY THIS MATTERS

理解 Big O 是漸近上界，並能比較常數、對數、線性、線性對數、平方與指數成長。

LEARNING GOALS

  • 用簡化規則求得常見 Big O
  • 依成長速度排列複雜度
  • 根據資料量判斷解法是否可能可行
01

Big O 描述成長上界

Big O 表示當輸入很大時，成本不會比某個成長等級更快，常用來描述最壞情況。像 3n + 20 在 n 變大後由 n 主導，因此寫成 O(n)；Big O 不等於精確執行時間，也不代表常數永遠不重要。

  • 忽略固定常數：O(3n) 簡化為 O(n)
  • 保留最高階項：O(n² + n) 簡化為 O(n²)
  • 不同輸入參數不能隨意合併：O(n + m) 應保留
02

認識常見成長速度

O(1) 不隨 n 增加，O(log n) 每一步大幅縮小問題，O(n) 逐筆處理，O(n log n) 常見於有效率排序，而 O(n²) 常來自比較所有配對。O(2ⁿ) 會隨 n 快速爆增，通常只能處理很小的輸入。

  • 較慢成長通常較能承受大型資料
  • log 的底數在 Big O 中通常省略
  • 同一成長等級的實際速度仍可能不同
Big O直覺典型例子
O(1)固定步驟依索引讀取 list
O(log n)每步縮小一半已排序資料的二分搜尋
O(n)逐筆看一次線性搜尋
O(n log n)分層且每層處理 n 筆合併排序
O(n²)處理所有配對雙層完整迴圈
O(2ⁿ)每項都有選或不選暴力列舉子集合
03

從限制反推可行解法

若 n 只有 20，指數解法有時仍能嘗試；若 n 接近十萬，通常要尋找 O(n) 或 O(n log n) 解法。這只是初步篩選，實際可行性還受常數、記憶體、語言與執行環境影響。

  • 先讀資料範圍，再設計演算法
  • 小輸入可以優先選簡單可靠的解法
  • 大型輸入應特別警覺巢狀完整走訪

RECAP

這堂課要帶走的事

  1. 01Big O 著重輸入很大時的主導成長項
  2. 02O(1) 到 O(2ⁿ) 的可擴展性差異非常大
  3. 03輸入限制能幫助排除不可能及時完成的解法

CHECK YOURSELF

先想一想，再看答案

5n² + 100n + 8 的 Big O 是什麼？

是 O(n²)，因為忽略常數後，n² 是 n 變大時的最高階主導項。

兩段依序執行、各走訪 n 筆資料的迴圈，為什麼是 O(n) 而非 O(n²)？

操作數是 n + n = 2n，忽略常數後為 O(n)；只有兩個完整迴圈互相巢狀時通常才是 O(n²)。

PRACTICE

延伸練習

  1. 將 O(n²)、O(1)、O(n log n)、O(log n)、O(n) 依成長速度由慢到快排序。
  2. 判斷列舉長度 n list 中所有索引配對的時間複雜度，並說明理由。

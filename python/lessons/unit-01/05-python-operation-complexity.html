Algorithm Foundations

Python 常見操作複雜度

相同語法看起來簡短，背後成本可能完全不同

入門25 分鐘PYTHON 3

WHY THIS MATTERS

掌握 list、dict、set、字串與 deque 的代表性操作成本，並知道平均 O(1) 仍有前提。

LEARNING GOALS

  • 辨認 Python 內建容器常見操作的複雜度
  • 解釋 list 頭尾操作成本不同的原因
  • 正確描述 dict 與 set 的平均查找成本
01

list 的索引快，搬移可能慢

Python list 是動態陣列，依索引讀寫通常是 O(1)，走訪與搜尋是 O(n)。尾端 append 平均為攤銷 O(1)，但在開頭 insert 或 pop 會搬移其餘元素，因此是 O(n)。

  • items[i]：O(1)
  • target in items：O(n)
  • items.append(value)：攤銷 O(1)
  • items.insert(0, value)：O(n)
02

dict 與 set 依賴雜湊

dict 與 set 使用雜湊表（Hash Table），查找、加入與刪除在平均情況通常是 O(1)。碰撞、擴充與惡劣輸入會影響成本，所以嚴謹表達應註明平均 O(1)、最壞 O(n)，也要記得鍵或元素必須可雜湊。

  • key in mapping：平均 O(1)
  • value in values_set：平均 O(1)
  • key in mapping.keys() 通常不需先建立新容器
  • 直接搜尋 mapping 的值仍可能是 O(n)
KEY IDEA

平均 O(1) 不表示每一次操作時間完全相同，而是長期平均不隨元素數量線性增加。

03

短語法也可能建立新資料

list 切片、字串切片與串接通常會依結果長度建立新物件，因此不能只看程式碼行數判斷成本。需要頻繁從佇列左端取值時，可使用 collections.deque 的 popleft 平均 O(1)，避免 list.pop(0) 的 O(n) 搬移。

  • items[a:b]：時間與空間皆約 O(k)
  • text_a + text_b：依結果長度配置新字串
  • list.pop(0)：O(n)
  • deque.popleft()：O(1)

RECAP

這堂課要帶走的事

  1. 01list 的索引為 O(1)，但頭端插入或刪除為 O(n)
  2. 02dict 與 set 的查找通常應描述為平均 O(1)
  3. 03切片與不可變字串操作可能配置與結果等長的新物件

CHECK YOURSELF

先想一想，再看答案

為什麼 list.pop(0) 是 O(n)？

刪除第一個元素後，其餘元素的位置需要向前搬移，因此搬移量會隨 list 長度成長。

要反覆判斷帳號是否已出現，list 和 set 通常選哪一個？

通常選 set，成員查找平均 O(1)；list 成員查找需要逐筆比對，為 O(n)。

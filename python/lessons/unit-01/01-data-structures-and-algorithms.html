Algorithm Foundations

資料結構與演算法是什麼

把資料的擺放方式與處理步驟分開思考

入門18 分鐘PYTHON 3

WHY THIS MATTERS

理解資料結構、演算法與 Python 程式碼各自扮演的角色，並練習把需求說成明確的問題。

LEARNING GOALS

  • 說明資料結構與演算法的差異
  • 辨認問題的輸入、輸出與限制
  • 理解同一問題可以有多種解法
01

資料需要有組織

資料結構（Data Structure）是組織資料的方式，會影響我們能多快新增、刪除、搜尋或依序讀取資料。Python 的 list、dict 與 set 就是不同取捨的資料結構；選擇結構前，應先問最常進行哪一種操作。

  • list 適合保留順序並用索引存取
  • dict 適合用鍵快速找到對應值
  • set 適合判斷某個值是否已出現
02

演算法是一組可執行步驟

演算法（Algorithm）是把輸入轉換成預期輸出的有限步驟，而且每一步都必須清楚到可以執行。食譜像演算法，但程式問題還需要明確界定輸入、輸出與限制，才有辦法檢查答案。

  • 輸入：演算法收到哪些資料
  • 輸出：完成後必須交出什麼結果
  • 限制：資料量、資料型態與特殊情況
KEY IDEA

Python 程式碼是演算法的一種實作；同一個演算法也能用其他程式語言表達。

03

先從可行解法開始比較

尋找名單中的姓名，可以逐筆檢查，也可以先排序後使用二分搜尋。兩者都可能正確，但建置成本、查詢速度與資料是否常變動不同；演算法學習的核心就是看懂這些取捨。

  • 先確認解法能處理所有合法輸入
  • 再比較執行時間與額外記憶體
  • 最後考量程式是否容易維護

CHECK YOURSELF

先想一想，再看答案

用學號查學生資料時，為什麼 dict 通常比 list 更自然？

dict 直接表達學號到學生資料的對應，平均情況下也能以 O(1) 查找；list 通常要逐筆比對而需 O(n)。

演算法和 Python 程式碼是同一件事嗎？

不是。演算法描述解題步驟，Python 程式碼則是用特定語言實作那些步驟。

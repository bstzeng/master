Classic String Algorithms

LPS Table：預先整理回退位置

在線性時間建立模式字串的自我資訊

進階40 分鐘PYTHON 3

WHY THIS MATTERS

定義 LPS 陣列，逐格建立最長 Proper Prefix／Suffix 長度，分析建表的攤銷 O(m)。

LEARNING GOALS

  • 說明 lps[i] 的精確意義
  • 正確實作匹配、回退與歸零分支
  • 以指標移動分析 O(m) 建表成本
01

LPS 每格代表什麼

LPS（Longest Proper Prefix which is also Suffix）陣列的 lps[i]，表示 pattern[:i + 1] 的最長 Proper Border 長度。lps[0] 必為 0，因為單字元字串沒有非空且不等於自身的 Proper Border。

  • 陣列長度等於 Pattern 長度 m
  • 值是長度，不是字串或索引
  • lps[i] 不會大於 i
  • 建表只依賴 Pattern 本身
02

匹配、回退與歸零

建表使用 index 探索下一字元、length 表示目前 Border 長度；字元相同時 Border 延長，失配且 length > 0 時回退到 lps[length - 1] 並重新比較，不移動 index。只有 length 已為 0 且仍失配時，才設定 lps[index] = 0 並前進。

  • 相同：length += 1，寫入後 index += 1
  • 失配且 length > 0：只回退 length
  • 失配且 length == 0：寫 0 並前進
  • 回退可能連續發生多次
03

為何建表是 O(m)

雖然失配分支可能讓 length 多次回退，但 index 只會前進到 m，而 length 的增加總量也受 index 前進次數限制，因此所有回退總量為線性。建表時間 O(m)、空間 O(m)，之後可用同一張表搜尋任意 Text。

  • index 從 1 單調前進到 m
  • length 的回退不會低於 0
  • 巢狀式回退不代表 O(m²)
  • 同一 Pattern 多次搜尋可重用 LPS

KEY IDEA

最常見錯誤是失配回退後仍讓 index 前進，這會漏掉較短 Border 的重新比較。

RECAP

這堂課要帶走的事

  1. 01lps[i] 是 pattern[:i + 1] 的最長 Proper Border 長度
  2. 02失配且 length > 0 時只回退 length，不移動 index
  3. 03LPS 可在 O(m) 時間及 O(m) 空間建立

CHECK YOURSELF

先想一想，再看答案

為什麼 lps[0] 一定是 0？

長度一的字串沒有非空且比自身短的前綴與後綴。

建表失配且 length > 0 時，下一步為何不是 length -= 1？

應直接跳到較短的已知 Border lps[length - 1]，略過已證明不可能的長度。

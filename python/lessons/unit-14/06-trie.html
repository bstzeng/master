Classic String Algorithms

Trie：以共同前綴組織單字

讓搜尋成本取決於查詢長度

進階40 分鐘PYTHON 3

WHY THIS MATTERS

建立 Trie 節點、插入、完整單字搜尋與前綴查詢，分析時間、空間與適用情境。

LEARNING GOALS

  • 解釋 Trie 如何共享共同前綴
  • 實作 insert、search 與 starts_with
  • 比較 Trie、Set 與排序 List 的選型
01

字元邊與終止標記

Trie（字典樹／前綴樹）從根開始，每條邊代表一個字元，具有共同前綴的單字共享同一路徑。節點除了 children 映射，還需 is_word 終止標記，才能區分已插入的完整單字與只是其他單字的前綴。

  • 根節點不代表任何字元
  • children 將字元映射到下一節點
  • is_word 標記完整單字結尾
  • 'app' 與 'apple' 共享前三個字元路徑
02

插入、單字搜尋與前綴搜尋

插入與查詢都從根依序走過每個字元，缺少分支時搜尋失敗，插入則建立節點；走完長度 L 的字串需要 O(L)。search 還要檢查 is_word，starts_with 只要整個前綴路徑存在即可。

  • insert：缺少節點時建立
  • search：路徑存在且 is_word 為 True
  • starts_with：路徑存在即可
  • 三種操作時間皆為 O(L)
03

空間成本與選型

Trie 的查詢時間與字串長度相關，不直接隨單字數線性成長，但每個節點的 children 結構可能帶來高常數空間；最壞節點數接近所有字元總量 S，即 O(S)。只問完整單字存在時 Set 更簡單，Autocomplete、前綴列舉或字典剪枝才特別適合 Trie。

  • 建樹時間與最壞空間 O(S)
  • 完整單字存在判斷：Set 平均 O(L) 且介面簡單
  • 前綴查詢與自動完成：Trie
  • 固定小字元集可用陣列 children，以空間換速度
結構完整單字查詢前綴查詢主要代價
Set平均 O(L)需額外掃描無前綴結構
排序 ListO(L log W) 比較量級可二分範圍更新較慢
TrieO(L)O(P) 到達前綴節點節點空間常數高
KEY IDEA

Trie 的 O(L) 很漂亮，但資料量小且沒有前綴需求時，Set 往往更實際。

CHECK YOURSELF

先想一想，再看答案

為什麼 Trie 節點需要 is_word，而不能只看路徑存在？

路徑可能只是較長單字的前綴；is_word 才能標記該位置本身是否為已插入的完整單字。

Trie 一定比 Set 適合單字存在查詢嗎？

不一定；只需完整單字存在判斷時 Set 更簡潔，Trie 的優勢主要在前綴操作與共享路徑。

PRACTICE

延伸練習

  1. 擴充 Trie，列出指定前綴下最多五個完整單字。
  2. 加入 remove 方法，處理刪除單字但保留其他共用前綴。

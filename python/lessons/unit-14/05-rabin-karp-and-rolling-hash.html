UNIT 14 / LESSON 05

Classic String Algorithms

Rabin–Karp 與 Rolling Hash

用固定長度視窗快速更新指紋

進階45 分鐘PYTHON 3

WHY THIS MATTERS

以多項式雜湊和滑動視窗實作 Rabin–Karp，理解平均線性時間、碰撞驗證與模數選擇。

LEARNING GOALS

  • 解釋 Rolling Hash 如何 O(1) 更新視窗
  • 實作帶碰撞驗證的 Rabin–Karp
  • 分析平均與最壞複雜度
01

雜湊先篩選候選

Rabin–Karp 把 Pattern 與每個同長 Text 視窗轉成數值指紋，雜湊不同即可確定字串不同，雜湊相同則再逐字元驗證。它把昂貴比較集中在少數候選，但雜湊相同不代表內容必然相同。

  • Pattern 與視窗長度都為 m
  • 雜湊不同可立即跳過
  • 雜湊相同必須驗證原字串
  • 適合多 Pattern 或需要字串指紋的延伸題型
02

Rolling Hash 更新視窗

視窗右移時，先扣除離開字元對最高位的貢獻，再乘 base 並加上進入字元，全部對 modulus 取餘數。預先算 high = base^(m - 1) mod modulus 後，每次更新只需 O(1)。

  • 移除 outgoing * high
  • 剩餘內容左移：乘 base
  • 加入 incoming 的字元碼
  • 每一步取模避免整數無限成長
03

完整搜尋、碰撞與複雜度

計算初始 Pattern 與第一個視窗雜湊需 O(m)，之後掃描視窗平均 O(n)，額外空間 O(1)；若大量碰撞導致每次都驗證 m 個字元，最壞仍為 O(nm)。選大質數模數、雙雜湊可降低碰撞機率，但要求完全正確時仍應保留字串驗證。

  • 平均時間 O(n + m)
  • 碰撞下最壞 O(nm)
  • 工作空間 O(1)，輸出另計
  • 雙雜湊降低風險但不等於數學上零碰撞
KEY IDEA

若省略碰撞驗證，演算法可能變成機率正確；教材版本保留驗證以確保答案。

RECAP

  2. 02Rolling Hash 能在視窗右移時 O(1) 更新指紋

CHECK YOURSELF

先想一想，再看答案

兩個字串雜湊值相同，能直接判定內容相同嗎？

不能；有限雜湊範圍必然可能碰撞，要求確定正確時要再比較原字串。

Rolling Hash 比每個視窗重新計算雜湊快在哪裡？

它利用前一視窗值，移除一字元並加入一字元，每次右移只需 O(1)，而非 O(m)。

PRACTICE

延伸練習

  1. 將 Rabin–Karp 改為使用兩組不同模數，只有雙雜湊相同才驗證。
  2. 刻意使用很小的 modulus 找出碰撞案例，確認驗證步驟能避免錯誤匹配。

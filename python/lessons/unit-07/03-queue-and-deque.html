Stacks, Queues, and Heaps

Queue 與 deque：先進先出

用雙端佇列避免線性位移

入門25 分鐘PYTHON 3

WHY THIS MATTERS

理解 FIFO 規則，以 collections.deque 實作 Queue 與雙端操作。

LEARNING GOALS

  • 說明 FIFO 與 Queue 的核心操作
  • 使用 deque 實作入隊與出隊
  • 比較 List 與 deque 的操作成本
01

FIFO 與排隊模型

Queue（佇列）遵守先進先出（First In, First Out，FIFO），最早加入的元素最先離開。它適合公平排程、訊息緩衝，以及依距離層級探索的廣度優先搜尋。

  • enqueue：從尾端加入
  • dequeue：從前端取出
  • front：查看下一個項目
  • 同一層工作依進入順序處理
02

為何使用 deque

List 的 pop(0) 會讓其餘元素前移，單次成本 O(n)；deque 專為兩端操作設計，append、appendleft、pop 與 popleft 都是 O(1)。保存 n 個待處理元素需要 O(n) 空間，但 deque 不適合頻繁存取中間索引。

  • list.append：攤銷 O(1)
  • list.pop(0)：O(n)
  • deque.append／popleft：O(1)
  • 隨機索引需求高時仍選 List
03

雙端操作與固定視窗

deque 是 Double-ended Queue，可在左右兩端常數時間增刪，因而也能實作 Stack 或固定長度緩衝區。設定 maxlen 後，加入新元素超過容量時會自動淘汰另一端最舊資料。

  • appendleft 適合插入緊急工作
  • rotate 可循環移動元素
  • maxlen 適合最近 N 筆紀錄
  • 雙端搜尋或中間刪除仍可能是 O(n)

CHECK YOURSELF

先想一想，再看答案

為什麼 List 不適合大量使用 pop(0)？

每次都要搬動其餘元素，單次為 O(n)，多次出隊可能累積成 O(n²)。

deque(maxlen=3) 已滿時再 append 會發生什麼？

新元素從右端加入，最左端最舊元素會被自動淘汰。

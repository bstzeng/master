Stacks, Queues, and Heaps

Priority Queue：依優先權取出

讓重要工作先處理，而非最早工作先處理

基礎30 分鐘PYTHON 3

WHY THIS MATTERS

以 heapq 實作 Priority Queue，處理相同優先權、穩定順序與可比較性問題。

LEARNING GOALS

  • 區分一般 Queue 與 Priority Queue
  • 使用 Tuple 建立優先權項目
  • 處理優先權相同與物件不可比較的情況
01

優先權改變取出規則

Priority Queue（優先佇列）不是依到達時間，而是每次取出目前優先權最高的項目。Python 的 heapq 是最小堆積，所以通常用較小數字代表較高優先權，查看下一項 O(1)，加入與取出 O(log n)。

  • 一般 Queue：依到達順序
  • Priority Queue：依優先值
  • heappush：O(log n)
  • heappop：O(log n)
02

穩定順序與 tie-breaker

當兩項優先權相同時，Tuple 會繼續比較下一欄；若工作物件不可互相比較，會發生 TypeError。加入遞增序號作為 tie-breaker，既能避免比較工作物件，也能讓同優先權項目依進入順序取出。

  • 項目格式：(priority, sequence, task)
  • sequence 永不重複，因此 task 不需互相比較
  • 較小 sequence 代表較早加入
  • 可用 itertools.count 產生序號
03

限制與使用情境

heapq 適合持續加入並反覆取出最高優先項目，但不擅長搜尋、刪除任意工作或直接更新既有優先權。排程、Dijkstra 最短路徑與事件模擬常用 Priority Queue；需要取消或更新時，常採延遲刪除並在彈出時忽略失效項目。

  • 查看 heap[0] 不會移除，O(1)
  • 搜尋任意項目為 O(n)
  • 內部 List 不是完整排序
  • n 次推入與取出總計 O(n log n)
結構下一項依據加入／取出
Queue最早到達O(1)／O(1)
Priority Queue最小優先值O(log n)／O(log n)
排序 List完整順序至少一端更新可能 O(n)
KEY IDEA

Priority Queue 保證下一個取出的項目，不保證整個容器隨時完整排序。

RECAP

這堂課要帶走的事

  1. 01Priority Queue 每次取出目前最高優先權，而非最早到達項目
  2. 02heapq 以較小值先出，加入與取出皆為 O(log n)
  3. 03遞增序號能穩定處理相同優先權與不可比較工作

CHECK YOURSELF

先想一想，再看答案

為何 (priority, task) 在 priority 相同時可能出錯？

Tuple 會繼續比較 task；若 task 是 Dictionary 等不可排序物件，就會拋出 TypeError。

Priority Queue 與一般 Queue 的主要差異為何？

一般 Queue 依 FIFO 取出，Priority Queue 依目前最高優先權取出。

  2. 模擬事件時間軸，以事件發生時間作為優先值逐項取出。

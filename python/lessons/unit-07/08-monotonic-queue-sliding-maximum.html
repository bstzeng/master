Stacks, Queues, and Heaps

Monotonic Queue 與滑動區間最大值

在線性時間維護視窗內的最佳候選

進階40 分鐘PYTHON 3

WHY THIS MATTERS

以遞減 deque 維護滑動視窗候選，實作 Sliding Window Maximum 並完成攤銷分析。

LEARNING GOALS

  • 說明 Monotonic Queue 的候選淘汰規則
  • 實作滑動區間最大值
  • 比較暴力、Heap 與 deque 解法
01

視窗最大值的兩種淘汰

Monotonic Queue（單調佇列）通常以 deque 保存索引，並讓對應值由前到後遞減，因此最前端永遠是目前最大值。移動視窗時要淘汰兩類候選：已離開左邊界的索引，以及被較新且不小的值支配的尾端索引。

  • 左端：移除已不在視窗的索引
  • 右端：移除值小於等於目前值的候選
  • 隊首：目前視窗最大值索引
  • 保存索引才能判斷是否過期
02

Sliding Window Maximum

對每個右端索引，先移除過期隊首，再從尾端移除不可能成為未來最大值的候選，最後加入目前索引。當視窗形成後，values[deque[0]] 就是答案；每個索引最多加入與移除一次，因此時間 O(n)、空間 O(k)。

  • 過期條件：index - candidates[0] >= k
  • 形成第一個視窗：index >= k - 1
  • 每個索引最多進出 deque 一次
  • k 必須介於 1 與資料長度之間
03

方法比較與延伸

每個視窗重新 max 需要 O(nk)；Heap 可用索引搭配延遲刪除做到 O(n log n) 或 O(n log k) 的變形；Monotonic Queue 利用滑動順序達到 O(n)。求視窗最小值時反轉尾端比較方向，同樣保存尚未過期且可能成為答案的候選。

  • 暴力法最直覺，適合驗證小案例
  • Heap 適合一般動態優先值，但過期刪除較複雜
  • Monotonic Queue 專長固定方向滑動視窗
  • 求最小值時維護遞增 deque
方法時間空間重點
每窗 maxO(nk)O(1)簡單但重複掃描
Heap約 O(n log n) 或 O(n log k)O(n) 或 O(k)需處理過期項目

KEY IDEA

尾端候選被較新且更大的值淘汰，是因為新值會更晚離開視窗，又不比舊值差。

CHECK YOURSELF

先想一想，再看答案

為何 Monotonic Queue 必須保存索引？

除了比較對應值，還要用索引判斷候選是否已離開視窗左邊界。

當新值大於舊的隊尾值時，為何舊隊尾可永久移除？

新值更大且位置更靠右，會比舊值更晚離開未來視窗，因此舊值不可能再成為最大值。

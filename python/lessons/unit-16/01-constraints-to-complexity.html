PYTHON / DATA STRUCTURES / ALGORITHMS
UNIT 16 / LESSON 01

Problem Solving and Algorithm Design

讀題與從限制推複雜度

先讀規格，再選工具

基礎25 分鐘PYTHON 3

WHY THIS MATTERS

把輸入、輸出、限制與資料性質轉為演算法需求。

LEARNING GOALS

  • 摘錄規格
  • 估計運算量
  • 辨認隱含性質
01

重寫問題契約

先用自己的話寫出輸入、輸出與合法條件，可避免解錯問題。特別標記是否有序、可重複、可修改與答案是否唯一。

  • 區分索引與數值
  • 確認空輸入及無解輸出
  • 辨認連續區間或任意子集合
02

由 n 估算上限

把複雜度換成粗略操作數：n=10⁵ 時 O(n²) 通常不可行，而 n≤20 可能允許 O(2ⁿ)。這是篩選候選方法，不是硬性時間保證。

  • 小 n 可考慮回溯
  • 大 n 常需 O(n) 或 O(n log n)
  • 同時檢查記憶體限制
03

限制也是提示

正數、已排序、無環或值域很小，都可能啟用特定技巧。選型前把每項推論寫成「因為限制 X，所以可用 Y」。

  • 已排序可能用二分或雙指標
  • 無權圖最短邊數用 BFS
  • 小值域可能用計數陣列
KEY IDEA

不要使用題目沒有保證的性質。

RECAP

這堂課要帶走的事

  1. 01先明確輸入輸出與邊界。
  2. 02用 n 排除不可行量級。
  3. 03資料性質是演算法選型依據。

CHECK YOURSELF

先想一想，再看答案

n=10⁵ 為何通常不選 O(n²)？

約 10¹⁰ 次工作，多數時限無法承受。

已排序為何重要？

它提供單調順序，可安全排除搜尋範圍。

PRACTICE

延伸練習

  1. 為三組不同 n 列出可能複雜度。
  2. 從一題規格整理輸入、輸出、性質與邊界。

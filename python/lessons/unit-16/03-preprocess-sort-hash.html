UNIT 16 / LESSON 03

Problem Solving and Algorithm Design

預處理、空間換時間、排序與 Hashing

先整理資料，再大量回答

基礎30 分鐘PYTHON 3

WHY THIS MATTERS

比較前綴和、排序與雜湊三種常見優化。

LEARNING GOALS

  • 辨認重複查詢
  • 評估排序成本
  • 選擇雜湊結構
01

預處理攤提成本

q 次區間和若每次掃描會到 O(nq)，先建 prefix 後總成本 O(n+q)。適合資料少更新、查詢很多。

  • 先付 O(n) 建表
  • 單次查詢降為 O(1)
  • 更新頻繁時需換結構
02

排序創造順序

排序 O(n log n) 後，可能使用雙指標、合併區間或二分搜尋。若需要原索引，可排序 (value,index) 而不是只排值。

  • 確認允許修改或使用副本
  • 一次排序可服務多次查詢
  • 排序不是免費步驟
03

Hashing 快速存在性

set 適合存在性，dict 適合鍵到計數或位置。平均 O(1) 查找換取 O(n) 空間，且不保證排序順序。

  • 去重用 set
  • 頻率與索引用 dict
  • 需要範圍順序時雜湊不一定合適

RECAP

這堂課要帶走的事

  1. 01重複查詢可用預處理攤提。
  2. 02排序能創造單調結構。
  3. 03set 與 dict 解決不同查詢語意。

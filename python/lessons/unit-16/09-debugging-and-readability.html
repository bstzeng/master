UNIT 16 / LESSON 09

Problem Solving and Algorithm Design

除錯、錯誤答案與可讀性

縮小差異，檢查狀態與不變量

基礎30 分鐘PYTHON 3

WHY THIS MATTERS

建立可重現、可追蹤、可修正的除錯流程。

LEARNING GOALS

  • 縮小失敗案例
  • 追蹤狀態
  • 改善程式表達
01

先重現再猜原因

記錄確切輸入、預期與實際輸出，將案例縮到仍失敗的最小版本。錯誤類別常是規格誤讀、邊界、狀態更新順序或資料結構選錯。

  • 一次只改一項
  • 確認失敗可穩定重現
  • 區分例外、超時與 Wrong Answer
02

印出有意義狀態

不要只印所有變數；選擇能檢查不變量的 left/right、queue、dp 列或 visited。把追蹤包在 debug 開關，修正後可關閉。

  • 比較更新前後
  • 標記迴圈與輸入位置
  • assert 可立即指出不變量破壞
03

可讀性降低缺陷

使用表達角色的命名、小函式與一致區間定義，讓程式接近正確性說明。避免壓縮成難以驗證的一行，也不要過早抽象。

  • complement 比 temp 更清楚
  • 註解解釋為什麼而非重述程式
  • 分離建表、求解與重建答案

RECAP

這堂課要帶走的事

  1. 01先取得最小可重現案例。
  2. 02追蹤能驗證不變量的狀態。
  3. 03清楚命名與分層能降低錯誤。

CHECK YOURSELF

先想一想，再看答案

為何縮小失敗案例？

可減少干擾並暴露真正觸發條件。

好註解應解釋什麼？

決策原因、限制或不直覺的不變量。

PRACTICE

延伸練習

  1. 將一段模糊變數名稱重構為角色名稱。
  2. 為 off-by-one 錯誤設計狀態追蹤。

Advanced Data Structures

Segment Tree 線段樹

用二元分割保存每個區間的聚合結果

進階38 分鐘PYTHON 3

WHY THIS MATTERS

建立支援點更新和區間聚合的 Segment Tree，理解 O(log n) 查詢來自少量完整覆蓋節點。

LEARNING GOALS

  • 說明節點區間與合併函式
  • 實作迭代區間和線段樹
  • 分析建置、更新與查詢成本
01

每個節點摘要一段資料

Segment Tree 將整個陣列區間反覆切半，葉節點代表單一元素，內部節點保存左右孩子聚合結果。只要 combine 具有結合性，就能用於 sum、min、max 或 gcd；不同聚合還需要正確的單位元素。

  • 根代表完整區間
  • 孩子代表左右半區間
  • combine 例如加法或 min
  • 樹高 O(log n)、空間 O(n)
02

迭代式陣列配置

將 n 個葉放在 tree[n:2n]，父節點 i 保存 tree[2i] 與 tree[2i+1] 的和。點更新從葉一路重算祖先；半開區間查詢遇到落單邊界就納入結果，再把 left、right 同時移到父層。

  • 建置 O(n)
  • 點更新 O(log n)
  • 區間查詢 O(log n)
  • 此版本聚合為加法
03

彈性來自可替換的聚合

把加法改成 min 時，未被選取區段的單位元素應是正無限大，而非 0；若要同時保存最大值與出現次數，節點可存 tuple 並自訂 combine。Segment Tree 比 Fenwick 程式複雜、常數較大，但能處理更多無法以前綴相減的聚合。

  • 單位元素必須符合 combine
  • 節點可以保存多欄摘要
  • 查詢只合併 O(log n) 個完整區段
  • 複雜區間更新需要 Lazy Propagation

RECAP

這堂課要帶走的事

  1. 01Segment Tree 的節點保存對應區間聚合
  2. 02建置 O(n)，點更新與區間查詢 O(log n)
  3. 03它比 Fenwick 更彈性，但實作與常數成本較高

CHECK YOURSELF

先想一想，再看答案

把區間和改成區間最小值時，為何空結果不能回傳 0？

0 可能小於實際元素而污染 min；單位元素應是正無限大，使 min(x,∞)=x。

Segment Tree 為何能在 O(log n) 查一段，而不是走訪每個葉？

查詢區間可拆成少量完整覆蓋的樹節點，每層最多處理固定數量邊界節點。

PRACTICE

延伸練習

  1. 將 SegmentTree 改為區間 minimum，調整建置、更新、查詢與單位元素。
  2. 設計節點 tuple，讓查詢同時回傳區間最大值與其出現次數。

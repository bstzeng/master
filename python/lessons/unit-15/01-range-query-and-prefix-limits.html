Range Query 與 Prefix Sum 的限制

查詢快不代表更新也快

中階28 分鐘PYTHON 3

WHY THIS MATTERS

定義區間查詢模型，複習前綴和並看懂靜態預處理在頻繁更新下的瓶頸。

LEARNING GOALS

  • 區分點更新與區間更新
  • 實作半開區間前綴和
  • 由操作比例選擇資料結構
01

先寫出操作介面

區間查詢（Range Query）不是單一演算法，而是一類在陣列某段上求和、最小值或其他聚合的需求。選資料結構前要確認查詢區間語意、是否更新、更新單點或整段，以及運算能否由兩個前綴結果相消。

  • Point Update：修改一個位置
  • Range Update：修改一整段
  • Range Query：聚合一段資料
  • 半開區間 [left,right) 與 Python 切片一致
02

Prefix Sum 用預處理換 O(1) 查詢

令 prefix[i] 表示前 i 個元素總和，則 [left,right) 的和是 prefix[right] - prefix[left]。建立一次需 O(n) 時間與 O(n) 空間，之後每次區間和為 O(1)，非常適合資料固定但查詢很多的情況。

  • prefix 長度為 n + 1
  • prefix[0] = 0 簡化邊界
  • 建置 O(n)、查詢 O(1)
03

更新使所有後綴失效

若 numbers[i] 改變，prefix[i+1:] 都需同步調整，單次更新成為 O(n)；反覆重建也同樣昂貴。只有追加資料時可 O(1) 延伸 prefix，而一般點更新加區間和應考慮 Fenwick Tree，更多聚合或區間操作則考慮 Segment Tree。

  • 靜態多查詢：Prefix Sum
  • 點更新加區間和：Fenwick Tree
  • 多種聚合或複雜更新：Segment Tree
  • 先估算更新次數 U 與查詢次數 Q

RECAP

這堂課要帶走的事

  1. 01Range Query 的選型取決於聚合、更新與區間語意
  2. 02Prefix Sum 以 O(n) 預處理換取 O(1) 區間和
  3. 03一般點更新會讓 Prefix Sum 的更新成本退化為 O(n)

CHECK YOURSELF

先想一想，再看答案

為何 prefix 陣列通常多配置一格？

prefix[0]=0 代表零個元素，讓從索引 0 開始的區間也能用同一個相減公式。

資料永不修改且有百萬次區間和查詢，應優先考慮什麼？

Prefix Sum，因為一次 O(n) 建置後，每次查詢只需 O(1)。

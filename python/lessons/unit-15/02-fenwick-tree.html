Advanced Data Structures

Fenwick Tree 樹狀陣列

用最低有效位元管理分段前綴和

進階35 分鐘PYTHON 3

WHY THIS MATTERS

實作 Fenwick Tree 的點更新、前綴和與區間和，理解一基索引和 O(log n) 路徑。

LEARNING GOALS

  • 解釋 lowbit 管理的範圍
  • 實作 add 與 prefix_sum
  • 分析 O(log n) 更新查詢
01

每格保存一段後綴區塊

Fenwick Tree（Binary Indexed Tree）用長度 n+1 的陣列保存多個部分和；一基索引 i 的 lowbit = i & -i，代表 tree[i] 涵蓋到 i 為止、長度為 lowbit 的區段。這些區段能拼出任意前綴，又能讓一次更新只影響 O(log n) 個節點。

  • 內部採一基索引
  • lowbit 決定節點負責範圍
  • 結構只需 O(n) 空間
  • 最適合可累積且可相消的操作
02

更新向上，查詢向前

點更新 add(index,delta) 將外部零基索引轉成一基後，反覆加 lowbit 更新所有包含該點的區塊；前綴查詢則反覆減 lowbit，累加互不重疊的區塊。兩條路每步消除或增加一個二進位低位，最多 O(log n) 步。

  • add 路徑：i += i & -i
  • prefix 路徑：i -= i & -i
  • range_sum 由兩個前綴相減
  • 負 delta 可表示減少
03

知道目前值才能做 set

Fenwick 原生操作是增加 delta；要把索引值設定為 new_value，可另存原陣列並加入 new_value-old_value。它的常數小、程式短，適合動態前綴和與頻率累積，但一般 range minimum 不可由兩個前綴相減，應改用 Segment Tree。

  • 點更新 O(log n)
  • 前綴與區間和 O(log n)
  • 空間 O(n)
  • 功能較專一但通常比 Segment Tree 輕量

RECAP

這堂課要帶走的事

  1. 01Fenwick 以 lowbit 將前綴拆成 O(log n) 個區塊
  2. 02點增加與前綴和都只走 O(log n) 個索引
  3. 03它適合可相消的累積操作，不是所有區間聚合都適用

CHECK YOURSELF

先想一想，再看答案

為何 tree 長度通常是 n+1？

Fenwick 內部用一基索引，索引 0 保留不用，使 lowbit 跳轉規則簡潔。

可以用兩個 prefix minimum 相減得到區間 minimum 嗎？

不能，最小值沒有像加法那樣的反運算；一般動態區間最小值應使用 Segment Tree。

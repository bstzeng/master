Advanced Data Structures

Lazy Propagation 與 Fenwick 比較

整段更新時先記帳，需要深入時再下推

進階34 分鐘PYTHON 3

WHY THIS MATTERS

理解 Lazy Propagation 如何避免逐點更新，並以操作需求比較 Prefix、Fenwick 與 Segment Tree。

LEARNING GOALS

  • 解釋延遲標記語意
  • 讀懂區間加總虛擬碼
  • 完成三種結構的選型
01

逐點更新會失去線段樹優勢

若要把 [left,right) 每個值都加 delta，逐點呼叫 set 需 O(k log n)。Lazy Propagation 在查詢區間完整覆蓋節點時，直接更新該節點摘要並留下 lazy 標記，只有之後部分進入孩子時才把影響下推。

  • 完整覆蓋時不再深入
  • lazy 記錄孩子尚未套用的更新
  • 部分覆蓋前先 push
  • 區間更新與查詢可達 O(log n)
02

摘要必須反映整段影響

區間加法搭配區間和時，長度 length 的節點總和要增加 delta*length，lazy[node] 再累加 delta。下推時把標記套到兩個孩子並清空父標記；更新規則與聚合不同時，標記的組合方式也要重新設計。

  • apply(node,delta)：更新摘要與標記
  • push(node)：把標記傳給孩子
  • update/query 遇部分覆蓋前先 push
  • 區間指定值與區間加法的標記不可直接混用
03

用最小足夠結構

靜態區間和選 Prefix Sum 最簡單；點加與區間和可選 Fenwick；需要 min/max、自訂節點或一般區間更新時選 Segment Tree，區間更新頻繁再加入 Lazy。若只需區間加與點查詢，也可用差分概念的 Fenwick，不能只按名稱決策。

  • Prefix：靜態、查詢 O(1)
  • Fenwick：精簡、點更新與前綴 O(log n)
  • Segment：聚合彈性、常數較大
  • Lazy Segment：區間更新強但除錯成本最高
需求建議結構代表成本
靜態區間和Prefix Sum查詢 O(1)
點加＋區間和Fenwick更新/查詢 O(log n)
點更新＋區間 minSegment Tree更新/查詢 O(log n)
區間加＋區間和Lazy Segment Tree更新/查詢 O(log n)

RECAP

這堂課要帶走的事

  1. 01Lazy 標記把完整覆蓋的區間更新延後到必要時下推
  2. 02節點摘要與標記都必須正確反映整段更新
  3. 03選型應使用最小足夠結構，避免不必要複雜度

CHECK YOURSELF

先想一想，再看答案

區間和節點長度為 8，整段加 3 時 tree[node] 增加多少？

增加 3×8=24，因為節點摘要是八個元素的總和。

只需動態點加與區間和，為何 Fenwick 常優於 Lazy Segment Tree？

Fenwick 已能以 O(log n) 完成且程式短、常數小；Lazy 的額外彈性在此沒有被使用。

PRACTICE

延伸練習

  1. 寫出 push 對左右孩子摘要及 lazy 標記的更新步驟。
  2. 為四種自訂工作負載選 Prefix、Fenwick、Segment 或 Lazy Segment 並說明。

Advanced Data Structures

Monotonic Stack 與 Queue 進階

及時移除再也不可能成為答案的候選

進階36 分鐘PYTHON 3

WHY THIS MATTERS

以單調堆疊解下一個較大值，以單調佇列解滑動視窗最大值，理解攤銷 O(n)。

LEARNING GOALS

  • 建立單調候選不變量
  • 實作 Next Greater 與 Sliding Window Maximum
  • 以進出次數分析攤銷成本
01

單調堆疊等待未來答案

Monotonic Stack 保存尚未找到下一個較大值的索引，並讓其對應值由棧底到棧頂遞減。新值較大時，棧頂的第一個較大值已確定並可彈出；每個索引只入棧、出棧各一次，所以整體 O(n) 而非巢狀表象的 O(n²)。

  • 保存索引可計算距離或回填答案
  • 彈出條件決定嚴格或非嚴格比較
  • 未被彈出者答案維持預設
  • 適合 Next Greater、每日溫度與柱狀圖
02

單調佇列維持視窗最大候選

滑動視窗最大值需要同時移除過期索引與較小的尾端候選。deque 中索引由舊到新、對應值由大到小，因此隊首永遠是目前最大值；新值進入時，被它壓過且更舊的較小值永遠不可能再成為最大值，可安全刪除。

  • 先移除 index-k 以前的過期索引
  • 尾端移除小於等於新值者
  • 隊首是當前視窗最大值
  • 每個索引最多進出一次
03

正確性來自支配關係

單調結構能快，是因為新候選能永久支配某些舊候選：它更晚過期且數值不小，因此舊候選不可能在未來勝出。若問題的比較規則不具有這種支配關係，強行維持單調會丟失答案；實作時也要先決定相等值保留新或舊索引。

  • Stack 處理單方向最近關係
  • Queue 處理移動視窗極值
  • while 總次數以每元素出棧一次做攤銷分析
  • 相等值政策影響索引與距離答案

RECAP

這堂課要帶走的事

  1. 01單調結構只保存仍可能成為未來答案的候選
  2. 02每個元素最多進出一次，使看似巢狀流程總時間 O(n)
  3. 03Monotonic Stack 適合最近較大/小，Queue 適合滑動視窗極值

CHECK YOURSELF

先想一想，再看答案

sliding_window_max 為何可以刪除尾端較小且更舊的值？

新值不小於它又更晚離開視窗，只要舊值仍在，新值也在且更適合當最大值，因此舊值永不會勝出。

程式中有 for 加 while，為什麼仍是 O(n)？

每個索引只入結構一次且最多被彈出一次，所有 while 迭代合計 O(n)，是攤銷分析。

  2. 把 sliding_window_max 改成滑動視窗最小值，列出比較符號要如何變更。

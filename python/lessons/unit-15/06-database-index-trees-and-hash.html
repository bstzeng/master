Advanced Data Structures

B-Tree、B+ Tree 與資料庫索引

讓每次磁碟讀取取得更多鍵，並支援範圍掃描

進階概念35 分鐘PYTHON 3

WHY THIS MATTERS

理解多路平衡樹配合儲存頁面的原因，並比較 Hash Index 與 Tree Index 的查詢能力。

LEARNING GOALS

  • 說明多路樹降低高度的原因
  • 區分 B-Tree 與 B+ Tree
  • 依等值或範圍查詢選索引
01

多路節點配合頁面 I/O

B-Tree 是平衡多路搜尋樹，一個節點保存許多排序鍵與孩子，使分支因子遠大於二元樹。資料庫與檔案系統把節點設計成接近一個儲存頁面，讓一次較昂貴的 I/O 載入大量鍵並降低整棵樹高度。

  • 所有葉位於相同深度
  • 節點滿時分裂、過少時合併或借鍵
  • 搜尋成本常以頁面 I/O 次數衡量
  • 高度約為 O(log_b n)，b 是高分支因子
02

B+ Tree 把資料集中在葉層

B-Tree 的內部與葉節點都可保存資料紀錄；B+ Tree 通常讓內部節點只保存導引鍵，實際資料或指標集中在葉節點，葉節點再以鏈結串起。較小的內部項目提高分支因子，而葉鏈結讓範圍查詢能從起點順序掃描。

  • 內部節點主要負責導航
  • 葉節點保存所有搜尋鍵資料
  • 葉層鏈結適合 ORDER BY 與範圍掃描
  • 實際資料庫格式依產品而異
03

Hash Index 與 Tree Index 各有所長

Hash Index 依雜湊值定位桶，適合完整鍵等值查詢，平均很快但不保留鍵順序；B+ Tree 類 Tree Index 的等值查詢多一段樹走訪，卻支援 <、>、BETWEEN、排序與前綴範圍。複合索引是否可用還受欄位順序與查詢規劃器影響。

  • 等值查詢：Hash 或 Tree 都可能適合
  • 範圍與有序輸出：Tree Index
  • 低選擇性欄位建索引未必有利
  • 索引會增加寫入與儲存成本
能力Hash IndexB+ Tree Index
完整鍵等值擅長擅長
範圍查詢通常不適合擅長
維持鍵順序否是
更新代價需維護桶需維護平衡與頁面

RECAP

這堂課要帶走的事

  1. 01B-Tree 以高分支因子降低昂貴頁面存取次數
  2. 02B+ Tree 的葉層鏈結使範圍與有序掃描有效率
  3. 03Hash Index 偏向等值，Tree Index 支援等值、範圍與排序

CHECK YOURSELF

先想一想，再看答案

B+ Tree 為何比二元搜尋樹更適合磁碟索引？

每個頁面可保存許多鍵與孩子，分支因子高、樹較矮，因此搜尋需要的頁面 I/O 較少。

查詢 WHERE age BETWEEN 20 AND 30，Hash Index 和 B+ Tree 通常選哪個？

通常選 B+ Tree，因為它保留鍵順序並能從下界開始連續掃描範圍。

Advanced Data Structures

LRU Cache 與 LFU Cache

用索引加順序結構在 O(1) 內淘汰資料

進階40 分鐘PYTHON 3

WHY THIS MATTERS

以 Hash Map 加 Doubly Linked List 實作 LRU，並比較 LFU 所需的頻率分桶。

LEARNING GOALS

  • 說明 LRU 的兩種操作需求
  • 實作 O(1) get/put
  • 理解 LFU 的額外狀態與平手規則
01

一個結構負責查找，一個負責順序

LRU Cache（Least Recently Used）容量滿時淘汰最久未使用項目。dict 讓 key 到節點查找平均 O(1)，Doubly Linked List 讓已知節點能 O(1) 移動或刪除；若只用 list，找鍵或移動通常會退化到 O(n)。

  • Hash Map：key → node
  • 雙向鏈結串列：最近使用順序
  • 頭端代表最近、尾端代表最久
  • 虛擬頭尾節點簡化邊界
02

get 與 put 都更新最近性

get 命中後把節點移到頭端；put 更新既有值也要移到頭端，新增超過容量時刪除尾端前一節點及 map 紀錄。每個步驟只操作固定數量指標與 dict，因此平均 O(1)，空間 O(capacity)。

  • remove 只需節點的 prev/next
  • add_front 固定接在 head 後
  • 淘汰時同時刪 map 與鏈結
  • capacity=0 應由介面明確處理
03

LFU 還要追蹤使用頻率

LFU Cache（Least Frequently Used）先淘汰頻率最低項目，頻率相同時常再淘汰其中最久未使用者。要達平均 O(1)，通常使用 key→node、frequency→該頻率的雙向串列，以及 min_frequency；命中時要把節點從 f 桶移到 f+1 桶。

  • LRU 只追蹤最近時間順序
  • LFU 追蹤頻率及同頻 LRU
  • 頻率老化政策會影響長期熱門項目
  • 更精確政策換來更高實作與記憶體成本

CHECK YOURSELF

先想一想，再看答案

LRU 為何使用雙向而非單向鏈結串列？

已知節點時要 O(1) 找到前後節點並移除；單向串列仍需搜尋前驅。

LFU 中兩個 key 頻率相同時通常如何淘汰？

常以同頻率桶內的 LRU 順序，淘汰其中最久未使用者；介面應明確規定。

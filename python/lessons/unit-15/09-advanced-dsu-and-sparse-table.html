Advanced Data Structures

DSU 進階與 Sparse Table

一個處理動態合併，一個加速完全靜態查詢

進階38 分鐘PYTHON 3

WHY THIS MATTERS

實作具路徑壓縮與按大小合併的 DSU，並理解 Sparse Table 的冪次區間預處理。

LEARNING GOALS

  • 實作最佳化 DSU
  • 建立靜態 RMQ Sparse Table
  • 依更新需求區分兩者及其他結構
01

DSU 維護動態連通分組

Disjoint Set Union（DSU）支援 find 查元素代表與 union 合併兩組。路徑壓縮讓 find 經過的節點直接指向根，按大小合併則把小樹接到大樹；兩者合用後每次操作攤銷 O(α(n))，在實務上近似常數。

  • parent 保存父節點
  • size 只在根節點有意義
  • find 壓縮查找路徑
  • union by size 控制樹高
02

Sparse Table 預算所有二次冪區間

Sparse Table 適合完全不更新的陣列，預先保存每個起點長度 2^k 的聚合；建置 O(n log n)、空間 O(n log n)。對 min/max 這類冪等運算，任意區間可用兩個可能重疊的最大冪區段合併，查詢 O(1)。

  • 冪等表示 combine(x,x)=x
  • RMQ 查詢選 k=floor(log2(length))
  • 兩段可重疊仍不影響 min/max
  • 一般 range sum 不能用重疊兩段公式
03

按問題的變動方向選型

DSU 解決的是集合只合併、不需拆分的動態連通性；Sparse Table 解決的是資料完全靜態、查詢極多的冪等區間聚合，兩者用途不同。需要線上更新的 RMQ 改選 Segment Tree，需要離線刪邊則可評估反向處理或更進階動態連通結構。

  • 只加邊連通性：DSU
  • 靜態大量 min/max：Sparse Table
  • 動態 RMQ：Segment Tree
  • DSU 不擅長刪除或分裂集合

RECAP

這堂課要帶走的事

  1. 01路徑壓縮加按大小合併使 DSU 操作攤銷近常數
  2. 02Sparse Table 用 O(n log n) 預處理換冪等 RMQ O(1)
  3. 03DSU 管連通合併，Sparse Table 管靜態區間，選型不可只看複雜度

CHECK YOURSELF

先想一想，再看答案

DSU 為何不適合直接刪除一條既有邊？

它只保存集合代表，沒有保存能判斷刪邊後是否仍連通的完整內部圖結構。

Sparse Table 的兩段重疊技巧為何適用 min 而不適用 sum？

min 是冪等的，重複元素不改變結果；sum 重複計算交集會讓答案過大。

PRACTICE

延伸練習

  2. 為 [5,2,7,1,3,6] 建立 Sparse Table 前三層並查詢 [1,5)。

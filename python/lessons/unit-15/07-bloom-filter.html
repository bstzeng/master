Advanced Data Structures

Bloom Filter 與 False Positive

用少量位元快速排除一定不存在的項目

進階34 分鐘PYTHON 3

WHY THIS MATTERS

實作簡化 Bloom Filter，理解多重雜湊、假陽性、無假陰性前提與選型。

LEARNING GOALS

  • 說明 Bloom Filter 的回答語意
  • 實作 add 與 membership
  • 解釋位元數、雜湊數與誤判率取捨
01

回答一定沒有或可能有

Bloom Filter 是機率型成員結構：加入元素時用 k 個雜湊位置設位元，查詢時若任一位為 0，元素一定未加入；全部為 1 只能說可能加入，因為其他元素可能碰巧設滿相同位置。

  • False Positive：未加入卻回答可能有
  • 標準只加不刪版本沒有 False Negative
  • 不保存原始元素
  • 適合在昂貴查詢前快速排除
02

多個穩定雜湊映射到 Bit Array

下例以 hashlib 對 seed 與字串編碼產生 k 個穩定位置，教學上用 bool list 代替真正壓縮位元陣列。add 和查詢都做 k 次雜湊，時間 O(k)，空間 O(m)，m 是位元數。

  • 相同值與 seed 必須產生相同位置
  • m 越大通常碰撞越少
  • k 太少或太多都可能提高誤判
  • 實務應使用真正 bit array 節省空間
03

容量規劃與刪除限制

元素越多，位元逐漸飽和，假陽性率會提高，因此應依預期元素數 n 和可接受誤判率配置 m、k。直接把位元清零可能傷到其他元素並造成假陰性；需要刪除可用 Counting Bloom Filter，但每格計數會增加空間。

  • Bloom 回答可能有後仍需查權威資料
  • 超過設計容量會快速降低品質
  • 不可直接刪位元
  • 不容許任何誤判時使用 set 或資料庫索引

RECAP

這堂課要帶走的事

  1. 01Bloom Filter 能確定不存在，但存在回答帶有假陽性
  2. 02操作成本 O(k)、空間 O(m)，品質取決於 m、k、n
  3. 03標準 Bloom 不支援安全刪除，也不取代權威資料來源

CHECK YOURSELF

先想一想，再看答案

Bloom Filter 回答 False 時，元素可能其實已加入嗎？

在標準只新增、實作正確且狀態未損壞的前提下不會；它沒有假陰性。

為什麼不能刪除元素時直接清除它的 k 個位元？

那些位元可能也被其他元素共享，清零會讓其他已加入元素被錯判不存在。

PRACTICE

延伸練習

  1. 用很小 bit_count 加入多個值，實際尋找一個 False Positive。
  2. 為爬蟲 URL 去重前置檢查設計 Bloom 與權威集合的兩層流程。

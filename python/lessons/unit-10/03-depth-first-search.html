Graph Fundamentals

Depth-First Search DFS

沿一條路深入，再退回探索其他分支

基礎30 分鐘PYTHON 3

WHY THIS MATTERS

使用遞迴與顯式 Stack 完成深度優先搜尋，理解 visited 的必要性。

LEARNING GOALS

  • 實作遞迴 DFS
  • 實作迭代 DFS
  • 分析鄰接表下的成本
01

深入前先標記 visited

深度優先搜尋（DFS）從起點沿未訪鄰居持續深入，沒有新路才返回。圖可能有環或多條路到同一點，因此必須在進入頂點時標記 visited，避免重複處理與無限循環。

  • 處理目前頂點後逐一探索鄰居
  • visited 保存已發現的頂點
  • 遞迴 Call Stack 自動保存返回位置
02

以 Stack 改寫迭代 DFS

顯式 Stack 版本把待探索頂點自行存入 list，適合避免深層遞迴限制。若在 pop 後才標記，頂點可能被重複推入；在加入 Stack 時標記可控制重複項目。

  • stack.pop() 取出最後加入的頂點
  • 加入鄰居時立刻標記 visited
  • 鄰居加入順序會影響走訪輸出，但不影響可達集合
03

成本與適用情境

採鄰接表時，每個可達頂點處理一次、每條邊查看固定次數，因此時間 O(V+E)，visited 與堆疊空間 O(V)。DFS 適合可達性、完整路徑探索、拓樸排序與結構性判斷，但不保證未加權圖的最短路徑。

  • 遞迴深度最壞 O(V)
  • 只從一個起點會忽略其他不連通元件
  • 需要回溯路徑時可額外保存 parent 或 path
KEY IDEA

DFS 的走訪順序不是唯一答案，取決於鄰接表中的鄰居順序。

RECAP

這堂課要帶走的事

  1. 01DFS 沿分支深入，visited 防止重複與繞圈。
  2. 02遞迴與顯式 Stack 都能實作 DFS。
  3. 03鄰接表下 DFS 時間 O(V+E)、額外空間 O(V)。

CHECK YOURSELF

先想一想，再看答案

圖的 DFS 為什麼通常需要 visited，而樹的 DFS 常可省略？

一般圖可能有環與多個父來源；樹從根向下時每個節點只有唯一父路徑，不會回到已訪節點。

DFS 能保證找到未加權圖最少邊數路徑嗎？

不能，DFS 可能先深入很長路徑；最少邊數應使用 BFS。

PRACTICE

延伸練習

  1. 用 DFS 判斷 target 是否能從 start 到達。
  2. 修改迭代 DFS 保存 parent，找到目標後還原一條路徑。

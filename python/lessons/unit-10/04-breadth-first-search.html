Graph Fundamentals

Breadth-First Search BFS

按距離層級由近到遠探索

基礎30 分鐘PYTHON 3

WHY THIS MATTERS

使用 deque 實作 BFS，並求未加權圖的最少邊數距離。

LEARNING GOALS

  • 使用 Queue 完成 BFS
  • 計算層級與最短距離
  • 判斷 BFS 的適用限制
01

Queue 維持先進先出

廣度優先搜尋（BFS）先探索起點，再探索距離一條邊、兩條邊的頂點。Queue 的先進先出順序維持這個層級，因此 Python 應使用 deque.popleft()。

  • 起點先加入 queue 與 visited
  • 取出 vertex 後加入所有未訪鄰居
  • 發現鄰居時立即標記，避免重複入列
02

未加權最短路徑

在所有邊成本相同的圖中，BFS 第一次發現頂點時走過的邊數必定最少。可令 distance[neighbor] = distance[vertex] + 1，並保存 parent 還原實際路徑。

  • distance[start] = 0
  • 第一次發現後不再更新距離
  • 有不同權重時不能直接使用一般 BFS
03

成本與使用時機

鄰接表下 BFS 時間 O(V+E)，distance、visited 與 queue 最壞使用 O(V) 空間。它適合未加權最短路徑、層級走訪與距離擴散；若只需任一可達路徑，DFS 也可能更簡潔。

  • Queue 最寬時可能同時保存 O(V) 頂點
  • 只會走訪 start 可達的區域
  • 多源 BFS 可把多個起點同時以距離 0 入列
需求常見選擇
任意可達路徑DFS 或 BFS
未加權最短邊數BFS
加權最短距離依權重選 Dijkstra 等演算法

CHECK YOURSELF

先想一想，再看答案

為什麼 BFS 應在加入 queue 時標記 visited？

若延後到取出時才標記，同一頂點可能被多個鄰居重複加入 queue。

邊權重為 1、10、1 時，一般 BFS 能求最小總權重嗎？

不能，BFS 最小化的是邊數，只有每條邊成本相同時才等同最小總權重。

延伸練習

  2. 在網格中從多個火源同時開始 BFS，計算每格最早被火到達的時間。

Sorting Algorithms

Heap Sort 與 Counting Sort

一個靠比較保證上界，一個利用有限整數範圍

中階35 分鐘PYTHON 3

WHY THIS MATTERS

比較堆積排序與計數排序的前提、實作方式，以及 O(n log n) 和 O(n + k) 的適用條件。

LEARNING GOALS

  • 用 heapq 實作堆積式排序
  • 實作支援負整數的計數排序
  • 根據值域 k 判斷計數排序是否合適
01

Heap Sort 反覆取出極值

堆積排序（Heap Sort）先建立能快速取得最小或最大值的 Heap，再反覆取出極值形成排序結果。下例使用 Python 最小堆 heapq，寫法簡潔但會複製資料；經典陣列 Heap Sort 可原地完成，通常不穩定。

  • 建堆可在 O(n) 完成
  • 每次 heappop 為 O(log n)
  • 總時間 O(n log n)
  • 此 heapq 版本額外空間 O(n)
02

Counting Sort 直接統計值域

計數排序（Counting Sort）不比較元素，而是統計每個整數值出現幾次，再依值域輸出。若 n 是元素數、k 是最大值與最小值的跨度，時間 O(n + k)、額外空間 O(k)；只有 k 相對可控時才划算。

  • 適用於可映射到小範圍的整數鍵
  • 偏移量可支援負整數
  • 值域很大時會浪費記憶體
  • 此直接重建值的版本不保留附屬資料穩定性
03

比較式與非比較式的界線

只透過兩兩比較的通用排序，在常見決策樹模型下最壞需要 Ω(n log n)；Heap Sort 達到這個等級。Counting Sort 使用值域資訊繞過比較下界，但必須付出 O(k) 空間，所以不是對所有資料都比 O(n log n) 排序更快。

  • Heap Sort 不要求小值域
  • Counting Sort 依賴有限離散鍵
  • k 遠大於 n 時避免 Counting Sort
  • 要穩定排序物件需使用累積計數與反向放置版本

RECAP

這堂課要帶走的事

  1. 01Heap Sort 提供 O(n log n) 最壞時間但標準版本不穩定
  2. 02Counting Sort 以 O(n + k) 時間換取 O(k) 值域空間
  3. 03非比較排序的速度來自對資料型態與範圍的額外假設

CHECK YOURSELF

先想一想，再看答案

一百個整數分布在 0 到十億，適合直接使用 Counting Sort 嗎？

不適合，k 約十億而 n 只有一百，計數陣列會消耗極大量且多數無用的空間。

heapq 版本與經典原地 Heap Sort 的空間性質相同嗎？

不同。此版本複製 heap 並建立結果，需 O(n) 額外空間；經典陣列版本可做到 O(1) 輔助空間。

PRACTICE

延伸練習

  1. 以 n 與 k 比較 Counting Sort 和 O(n log n) 排序可能的適用範圍。
  2. 用 heapq 寫出只取最小 k 個元素的函式，說明是否需要完整排序。

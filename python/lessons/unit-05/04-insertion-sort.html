Sorting Algorithms

Insertion Sort 插入排序

把下一張牌插入已排序前綴

入門23 分鐘PYTHON 3

WHY THIS MATTERS

使用搬移而非反覆交換實作插入排序，並認識近乎有序資料的優勢。

LEARNING GOALS

  • 說明已排序前綴不變量
  • 實作穩定原地插入排序
  • 分析近乎有序資料的成本
01

維持已排序前綴

插入排序（Insertion Sort）把第一個元素視為已排序，接著取出下一個 key，將較大的前綴元素向右搬，再把 key 插入空位。每輪結束後，從索引 0 到目前位置都已排序。

  • 像整理手中撲克牌
  • 一次把一個新元素插入前綴
  • 前綴在每輪結束後保持排序
02

只搬移嚴格較大的元素

保存 key 後，while 迴圈將所有大於 key 的元素右移；遇到小於等於 key 的元素就停止。相等鍵不跨越彼此，因此此版本穩定，且所有操作都在原 list 內完成。

  • 先保存即將被覆蓋的 key
  • 搬移比逐次交換更直接
  • 使用 > 維持相等鍵順序
03

成本取決於逆序程度

已排序時每個 key 只比較一次，最佳時間 O(n)；反向排序時每輪幾乎搬移整個前綴，最壞 O(n²)，平均也是 O(n²)。額外空間 O(1)，小型或近乎有序資料上常有良好表現。

  • 最佳時間 O(n)
  • 平均與最壞時間 O(n²)
  • 額外空間 O(1)
  • 穩定且原地

RECAP

這堂課要帶走的事

  1. 01插入排序逐步擴張已排序前綴
  2. 02只搬移嚴格較大元素可維持穩定性
  3. 03它適合小型或近乎有序資料，但最壞為 O(n²)

CHECK YOURSELF

先想一想，再看答案

插入排序在已排序資料為何是 O(n)？

每個 key 與前一元素比較後就停止，不需要搬移，總共只做線性次數工作。

若 while 條件改成 items[position] >= key，穩定性會如何？

相同鍵也會被右移，新元素可能跑到舊元素前面，因此失去穩定性。

PRACTICE

延伸練習

  1. 手動推演 [3, 1, 2, 5, 4] 的 key 與前綴變化。
  2. 計算一組近乎有序輸入實際發生的搬移次數。

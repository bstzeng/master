Sorting Algorithms

排序演算法總比較

根據輸入與需求選方法，而不是尋找唯一冠軍

中階28 分鐘PYTHON 3

WHY THIS MATTERS

整合所有排序方法的時間、空間、穩定性與適用資料，建立實務選擇流程。

LEARNING GOALS

  • 比較經典排序的關鍵性質
  • 依限制排除不合適方法
  • 說明內建排序通常優先的原因
01

共同表格先看硬性限制

選擇排序時先看資料量、最壞時間、額外空間、穩定性與鍵值限制。表格描述本單元的典型實作；同名演算法可能因 partition、合併方式或實作細節而改變空間與穩定性。

  • n 大時先排除 O(n²)
  • 需要穩定性時排除標準 Selection、Quick 與 Heap Sort
  • 記憶體緊張時注意 Merge 與 Counting 的額外空間
演算法最佳時間平均／最壞時間額外空間穩定
BubbleO(n)O(n²)／O(n²)O(1)是
SelectionO(n²)O(n²)／O(n²)O(1)否
InsertionO(n)O(n²)／O(n²)O(1)是

02

從資料特性做決定

小型或近乎有序資料可考慮 Insertion Sort；需要穩定且可預測的 O(n log n) 可選 Merge Sort；有限整數值域且 k 不大時 Counting Sort 可能很好。若只是一般 Python 應用，內建 Timsort 已針對真實資料與部分有序情況最佳化。

  • 近乎有序：Insertion 或 Python 內建排序
  • 穩定且一般資料：Merge 或內建排序
  • 小整數值域：評估 Counting Sort
  • 教學實作有助理解，但不代表應取代成熟函式庫
03

排序也包含整體成本

不要只比較排序函式本身：昂貴 key 若重複計算、複製大型資料、先排序卻只查詢一次，都可能主導成本。先明確說明輸入是否可修改、是否需完整排序，以及能否只用 heap 取 Top K，才能選到真正合適的方案。

  • 只需最小或最大值時不必完整排序
  • 只需 Top K 可評估 heap
  • 不可修改輸入時需計入副本空間
  • 效能判斷最後應以真實資料量測驗證

RECAP

這堂課要帶走的事

  1. 01排序沒有單一最佳方法，選擇取決於資料與限制
  2. 02穩定性、原地性和最壞上界都是重要決策條件
  3. 03一般 Python 程式優先使用內建排序，特殊需求再採專門方法

CHECK YOURSELF

先想一想，再看答案

需要保留相同分數學生的報名順序，應優先關注哪個性質？

穩定性；穩定排序會保留相同排序鍵元素的原相對順序。

只需要一百萬筆中的十個最大值，為何不一定要完整排序？

可用大小為 10 的 heap 維持 Top K，通常只需 O(n log 10)，避免完整排序的 O(n log n)。

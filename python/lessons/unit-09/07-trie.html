Tree Data Structures

Trie 字典樹

讓共同前綴共用路徑

中階32 分鐘PYTHON 3

WHY THIS MATTERS

以字元邊建立 Trie，實作新增、完整單字與前綴查詢，分析長度與空間成本。

LEARNING GOALS

  • 說明 Trie 的前綴共享
  • 實作 insert、search 與 starts_with
  • 比較 Trie 與 set 的適用情境
01

路徑代表前綴

Trie 又稱 Prefix Tree，從根沿字元邊走過的路徑代表字串前綴，因此 apple 與 app 共用 a、p、p 節點。節點需要終止標記區分完整單字和單純前綴，否則插入 apple 後會誤認 app 已存在。

  • 根節點不代表特定字元
  • 孩子映射由下一字元找到節點
  • is_end 標記完整單字
  • 共同前綴只儲存一次路徑
02

新增與查詢走相同路徑

insert 遇到不存在的字元就建立節點；search 走完整個單字後還要檢查 is_end；starts_with 只需確認前綴路徑存在。若字串長度為 L，三者時間皆 O(L)，與 Trie 中總單字數沒有直接線性關係。

  • setdefault 可取得或建立孩子
  • 完整查找需要 is_end
  • 前綴查找不要求終止標記
  • 空字串政策應由介面明確定義
03

前綴能力換取節點成本

Trie 適合自動完成、字典前綴篩選與逐字搜尋，但每個節點的 dict 會帶來可觀的物件成本。最壞節點數接近所有字串長度總和 S，空間 O(S)；若只需精確成員查找，set 通常更簡單且記憶體常更實用。

  • 前綴列舉是 Trie 的核心優勢
  • 空間最壞 O(S)
  • 字元集與節點表示影響常數成本
  • 精確查找可先考慮 set

RECAP

這堂課要帶走的事

  1. 01Trie 讓多個字串共用相同前綴路徑
  2. 02is_end 用來區分完整單字與前綴
  3. 03操作時間 O(L)，但可能使用接近總字元數的節點空間

CHECK YOURSELF

先想一想，再看答案

插入 apple 後，starts_with('app') 與 search('app') 各是什麼？

starts_with 為 True，search 為 False，除非 app 也曾被完整插入並標記 is_end。

只需判斷完整帳號是否存在，為何 set 可能優於 Trie？

set 介面更直接，平均精確查找快，且不需為每個前綴建立節點物件。

PRACTICE

延伸練習

  1. 擴充 Trie，列出指定 prefix 下最多 k 個完整單字。
  2. 設計刪除單字流程，思考何時能安全移除不再共用的節點。

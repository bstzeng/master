Tree Data Structures

平衡樹的基本概念

限制高度，讓搜尋成本不因插入順序失控

中階28 分鐘PYTHON 3

WHY THIS MATTERS

理解 AVL Tree 與 Red-Black Tree 如何用旋轉及額外規則維持對數高度。

LEARNING GOALS

  • 解釋平衡與操作成本的關係
  • 理解旋轉保留 BST 次序
  • 比較 AVL 與 Red-Black Tree 的取捨
01

平衡的目標是控制高度

平衡搜尋樹（Balanced Search Tree）不是要求左右節點數完全相等，而是透過規則讓高度保持 O(log n)。如此查找、插入與刪除即使面對不利順序，也能避免普通 BST 退化成長鏈。

  • 核心保證是高度 O(log n)
  • 維護平衡需要額外資訊與調整
  • 平衡條件依樹種而不同
  • 不是所有二元樹都需要排序性
02

旋轉改形狀但保留順序

左旋與右旋是局部重新連接節點的操作，能降低過高一側，同時保持中序鍵順序不變。AVL Tree 以左右子樹高度差限制平衡，插入或刪除後依失衡形態使用單旋或雙旋。

  • 旋轉只修改常數個連結
  • 局部旋轉本身為 O(1)
  • 更新高度或平衡因子不可遺漏
  • LL、RR、LR、RL 對應不同修正
03

AVL 與 Red-Black 的取捨

AVL Tree 平衡較嚴格，通常查找深度較小，但更新可能需要較多調整；Red-Black Tree 使用顏色與路徑規則維持較寬鬆的 O(log n) 高度，常用於通用有序映射。Python 內建 dict 是雜湊表，並未直接提供這兩種樹。

  • AVL：高度控制較嚴格
  • Red-Black：更新與查找取折衷
  • 兩者核心操作最壞 O(log n)
  • 需要排序鍵、範圍查詢時樹比雜湊表更自然
結構平衡方式主要特性
普通 BST無可能退化 O(n)
AVL Tree高度差較嚴格平衡
Red-Black Tree顏色與路徑規則較少嚴格但仍 O(log n)

RECAP

這堂課要帶走的事

  1. 01平衡樹的重點是將高度限制在 O(log n)
  2. 02旋轉能調整局部形狀而不破壞 BST 中序順序
  3. 03AVL 與 Red-Black 使用不同規則交換查找高度與更新成本

CHECK YOURSELF

先想一想，再看答案

平衡樹是否要求每個節點左右子樹節點數完全相同？

不要求；不同平衡樹用不同條件控制高度，目標是避免高度退化。

旋轉為何不破壞 BST 排序？

它只改變局部父子關係，並依鍵的大小重新連接，使該區域中序走訪順序保持不變。

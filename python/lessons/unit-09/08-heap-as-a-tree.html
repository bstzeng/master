Tree Data Structures

Heap 與樹的關係

用完全二元樹形狀在陣列中維持極值

中階30 分鐘PYTHON 3

WHY THIS MATTERS

理解 Binary Heap 的形狀與順序性質、陣列索引關係，以及它和 BST 的根本差異。

LEARNING GOALS

  • 說明完全二元樹與 Heap Property
  • 使用索引找到父子節點
  • 依需求區分 Heap 與 BST
01

Heap 同時限制形狀與局部順序

二元堆積（Binary Heap）是完全二元樹，除最後一層外全部填滿，最後一層由左向右填。最小堆只保證每個父節點不大於孩子，因此根是全域最小值，但兄弟與不同子樹之間沒有完整排序。

  • 完全形狀讓高度保持 O(log n)
  • 最小堆根為最小值
  • 最大堆根為最大值
  • Heap 不是 Binary Search Tree
02

完全形狀適合陣列索引

以零起始陣列儲存 Heap 時，索引 i 的左孩子為 2i + 1、右孩子為 2i + 2，父節點為 (i - 1) // 2，因此不需保存指標。插入後向上調整，移除根後把末元素移到根再向下調整，兩者都沿樹高花 O(log n)。

  • 讀取根為 O(1)
  • 插入為 O(log n)
  • 移除根為 O(log n)
  • 搜尋任意值最壞 O(n)
03

Heap 與 BST 解決不同查詢

Heap 擅長反覆取得極值，常用於 Priority Queue、Top K 與排程；它不能沿左右關係有效尋找任意鍵。平衡 BST 能進行 O(log n) 精確查找、前後鄰居與範圍查詢，但維護規則更複雜；選擇應由最常操作決定。

  • 只反覆取最小／最大：Heap
  • 需要有序範圍與任意鍵：平衡 BST
  • Heap 建立可用 heapify O(n)
  • Python heapq 不保證迭代輸出有序

讀取最小值O(1)（最小堆）O(log n) 或保存指標

CHECK YOURSELF

先想一想，再看答案

最小堆的第二小值一定在陣列索引 1 嗎？

不一定；它可能在根的左或右孩子，Heap 只保證父不大於孩子。

為什麼 Heap 中搜尋任意 target 最壞是 O(n)？

局部父子順序不足以判斷 target 應在左或右子樹，最壞可能需要檢查所有節點。

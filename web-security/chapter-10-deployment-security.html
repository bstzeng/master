COURSE OUTLINE / CHAPTER 10

SECURE THE DELIVERY PIPELINE

主機、雲端與部署安全

正式網站的安全不只取決於應用程式。網域、Git、CI Runner、Artifact、雲端 IAM、Secret、Container 與部署平台都能改變正式環境，任何一段失守都可能繞過網站本身的防線。

90–120 分鐘8 個完整段落平台與供應鏈授權環境限定

LEARNING OUTCOME

完成本章後，你能畫出自己的 Source-to-Production 流程，盤點網域、TLS、管理入口、IAM、Secret、依賴、Build、Artifact 與 Runtime，並建立最小權限、短效憑證、變更審核、可追溯 Artifact 與回滾基準。

SAFE PRACTICE BOUNDARY

只檢查自己的 Repository、雲端帳號、託管平台與設定。不要探測他人主機、嘗試登入陌生 SSH 或下載未知 Artifact；課程不提供取得、提升或維持系統權限的步驟。

01

MODEL THE DELIVERY PATH

能發布正式環境的每一個身分，都是高價值控制面

交付鏈從開發者裝置、Git 帳號、Branch、Pull Request、CI Workflow、Runner、依賴來源、Build Artifact、Registry、Deploy Identity 到 Runtime。攻擊者若取得其中任何高權限 Token，可能不經網站 Endpoint 就直接改變程式、設定或雲端資源，因此控制面通常比單一會員帳號影響更大。

先畫出每個階段的輸入、產物、身分、核准、Secret、日誌與下一跳，標出哪些步驟能寫入正式、誰能修改 Workflow、誰能建立 Release，以及緊急回滾如何執行。NIST SSDF 強調把安全實務整合進既有 SDLC，而不是在上線最後一天才做一次掃描。

受保護帳號、簽署、審核與分支規則

BUILD隔離 Runner

鎖定依賴、最小 Token、無持久 Secret

ARTIFACT可追溯產物

雜湊、簽章、來源與不可變版本

DEPLOY短效正式權限

核准、環境保護、稽核與回滾

圖 1｜Source-to-Production 每次從資料變成可執行產物、從低權限進入高權限，都要留下可驗證的信任證據。

02

PROTECT THE NAME AND CHANNEL

網站程式還在，網域或憑證失守仍能讓流量走錯地方

網域註冊商與 DNS 能決定流量、郵件和憑證驗證方向，應使用獨立管理帳號、抗釣魚 MFA、最小管理者、異動通知、Registrar Lock 與可恢復聯絡方式。DNS Zone 需要擁有者與變更紀錄，測試、舊版與第三方驗證記錄要有到期日，避免遺留指向已釋放資源。

TLS 自動續期不代表可以不管理：盤點所有 Hostname、憑證簽發方式、私鑰位置、到期告警和終止 TLS 的元件。Edge 到 Origin 也應驗證加密與服務身分，不能因外層已有 HTTPS 就用不受信任明文。啟用 HSTS 前確認所有子網域相容，並測試憑證輪替和緊急撤銷。

REGISTRAR網域所有權

抗釣魚 MFA、鎖定、通知與復原聯絡人

DNS流量指向

變更審核、擁有者、TTL 與廢棄記錄清理

CERTIFICATE服務身分

自動續期、私鑰保護、到期與撤銷演練

ORIGINEdge 後方通道

驗證 TLS、限制來源，不信任任意內網流量

圖 2｜名稱與通道的四個擁有者 網域、DNS、TLS 與 Origin 是連續信任鏈，缺少任何一段都可能讓使用者連到錯誤服務。

03

REDUCE ADMINISTRATIVE ACCESS

公開管理面越少，長期維護成本越低

主機管理優先使用雲端 Session Manager、Bastion 或身分感知代理，集中 MFA、短效授權與稽核；若必須 SSH，關閉密碼登入與 Root 遠端登入，限制來源、使用個人金鑰或短效憑證，不共用帳號。離職、裝置遺失與金鑰輪替要有可執行流程。

主機以最小化映像建立，移除不需要服務與 Port，啟用自動安全更新或明確 Patch SLA，配置防火牆、時間同步、集中日誌、磁碟空間告警與完整備份。不要手工修改正式主機形成不可重建的 Snowflake；配置應版本化，變更經過審核並能從乾淨映像重新部署。

ACCESS身分感知入口

MFA、裝置條件、來源限制與完整 Audit

CREDENTIAL短效個人權限

不共用帳號、不長期散發 Root Key

HOST最小化基準

必要服務、Patch、Firewall、Log 與資源監控

REBUILD配置版本化

Immutable Image／IaC，可從乾淨狀態重建

圖 3｜主機管理的安全路徑 管理能力要集中、短效、個人化且可稽核，正式主機則盡量不可變。

04

ACCESS MUST BE JUSTIFIED

人、Pipeline 與 Runtime 應使用不同且最小的身分

雲端 IAM 先分人類管理者、CI Deploy Identity 與 Runtime Service Account。人類使用 SSO、MFA 與需要時提升的管理角色；CI 透過 OIDC Federation 取得與 Job 綁定的短效憑證；Runtime 使用工作負載身分，只能讀寫該服務必要資源，不共享一組長期 Access Key。

Policy 不使用全域 Resource 與 Action，拆分讀、寫、管理與 Key 使用；定期比較已授權與實際使用權限，清理 Dormant Identity。高影響變更需要雙人審核、時間限制與告警。跨帳號與第三方存取明確設定 Trust Condition、Audience 與 External ID，避免一個合作方憑證擴大到所有環境。

HUMANSSO＋MFA

日常低權限，需要時短暫提升並稽核

PIPELINEOIDC 短效憑證

綁 Repository、Branch、Environment 與 Job Claims

RUNTIME工作負載身分

每服務、每環境拆分，只能存取必要資源

THIRD PARTY明確 Trust

條件、範圍、期限、擁有者與撤銷流程

圖 4｜身分依用途拆分 不讓同一長期憑證跨人、Pipeline、Runtime 與環境，才能清楚歸因與快速撤銷。

05

SECRETS ARE TEMPORARY CAPABILITIES

Secret 不只要藏起來，還要能發放、使用、輪替與撤銷

API Key、資料庫密碼、私鑰、Webhook Secret 與簽章金鑰不可硬編碼在程式、Image、CI 設定或 Log。使用 Secret Manager 集中儲存、加密、權限、版本、稽核與輪替；應用在 Runtime 以工作負載身分取得，只拿所需 Secret，避免整包環境變數長期暴露。

每個 Secret 要有擁有者、用途、Consumer、環境、權限、建立與到期、輪替方式、撤銷與備援。優先使用短效動態憑證；不得不使用長效值時也依服務與環境拆分。發現外洩先撤銷或輪替，再檢查使用紀錄、更新依賴和清理歷史；遮罩 Log 不能取代從源頭避免輸出。

CREATE專用且最小

每服務／環境拆分，安全亂數與明確用途

DELIVER身分式取得

Runtime 以工作負載身分讀取，不進 Repository

USE不輸出不持久

避免 Log、Shell History、Artifact、Image 與 Debug

ROTATE自動輪替與撤銷

雙版本過渡、驗證 Consumer、異常立即失效

圖 5｜Secret 生命週期 中央管理只是起點；短效、最小範圍、可歸因與可撤銷才真正降低外洩影響。

06

KNOW WHAT YOU SHIP

套件名稱、版本、來源與 Build 工具都屬於正式程式

依賴採最小集合、固定版本與 Lockfile，只從核准 Registry 下載；評估套件維護狀態、授權、發布者與替代方案。自動化 Vulnerability Alert 要有擁有者與修補 SLA，但升級也要經測試，不因機器人開 PR 就直接取得發布權。產生 SBOM 能在新漏洞出現時快速確認受影響產品。

Build 環境應乾淨且可重現，驗證下載雜湊或簽章，避免把不受信任 PR Code 與正式 Secret 放在同一高權限 Workflow。Artifact 產生後記錄來源 Commit、Workflow、依賴與雜湊，後續環境 Promote 同一個 Artifact，而不是在每個環境重新 Build 不同內容。

SOURCE核准依賴

Lockfile、Registry、Maintainer、License 與最小集合

BUILD隔離且可重現

乾淨 Runner、無正式 Secret、固定工具與雜湊驗證

PROVENANCEArtifact 來源

Commit、Workflow、Builder、依賴與簽章可追溯

SBOM元件清單

漏洞出現時快速找受影響版本與服務

圖 6｜知道正式環境到底跑什麼 從核准來源到不可變 Artifact 保留證據，事件時才能快速定位與重建。

07

THE PIPELINE IS PRODUCTION

能改 Workflow 的人，可能等同能使用部署 Secret

CI/CD 以最小 Token 權限起步，第三方 Action／Plugin 固定到不可變版本，避免執行未審查的 Fork Code 時取得 Secret 或寫入權限。Workflow 檔、部署腳本與 IaC 都需要 Code Owner Review；正式 Environment 要有核准、Branch／Tag 規則、Concurrency Lock 與可追蹤 Deployment Record。

Runner 優先短命且隔離，Job 結束即銷毀；Cache 與 Artifact 分開信任層級，避免低權限 Workflow 污染高權限 Build。Log 自動遮罩並限制下載權，Debug 模式有期限。部署前驗證 Artifact 簽章與安全檢查，部署後執行 Smoke Test；失敗能自動停止並回滾到已知良好版本。

WORKFLOW審核與固定版本

Code Owner、不可變 Action、禁止未審查高權限執行

TOKEN最小且短效

預設 Read-only；正式權限只在核准 Job 取得

RUNNER隔離與短命

Job 後銷毀，Cache 不跨不可信邊界

ENVIRONMENT核准與回滾

Artifact 驗證、Smoke Test、紀錄與已知良好版本

圖 7｜把 Pipeline 當正式系統 Workflow、Runner、Cache、Artifact 與 Environment 都有不同信任層，不能混用權限。

08

VERIFY THE PLATFORM

把帳號、設定、更新、備份與回滾變成持續檢查

建立平台清單：Domain、DNS、Certificate、Git、CI、Registry、Cloud Account、IAM Role、Secret、Runtime、Database、Storage、Logging、Backup 與擁有者。每項記錄公開可達性、最高權限、MFA、變更方式、Patch／版本、日誌、備份、恢復目標和下線方式。

以 Policy-as-Code／IaC Check、Secret Scanning、Dependency Review、Image Scan 與設定漂移偵測建立自動基準，但每季仍人工檢查高權限身分、Dormant Key、第三方 Trust 與復原聯絡人。每次重大變更至少能回答：誰核准、部署了哪個 Artifact、用哪個身分、變更哪些資源、如何監控、如何回滾。

IDENTITY高權限可歸因

SSO、MFA、短效、最小權限、Dormant 清理

CONFIG版本化且受審

IaC、Policy、漂移偵測與變更紀錄

SOFTWARE已知且可追溯

Patch SLA、依賴、SBOM、Artifact 與 Runtime 版本

RECOVERY可以真正回去

備份、還原、回滾、替代聯絡與演練結果

CHECK YOUR MODEL

先回答，再展開。

網站沒有 SSH Port，是否代表部署層安全？

不代表。Git、CI、Registry、Cloud IAM、DNS 和託管平台帳號都可能直接改變正式環境。

把 Secret 放在 CI 的 Secret 欄位就永遠安全嗎？

不是。仍需最小權限、短效、限制可用 Workflow、避免 Log／Fork 洩漏並定期輪替。

為什麼正式環境應 Promote 同一個 Artifact？

可確保測試與正式使用相同位元，並保留可追溯來源，避免各環境重新 Build 出差異。

Runtime 為什麼不應使用 CI 的部署憑證？

兩者用途與權限不同；共用會擴大爆炸半徑並失去歸因。

自動掃描通過就能跳過人工審核嗎？

不能。自動化適合一致檢查，架構、權限、第三方 Trust 與業務風險仍需人做判斷。

DATA IS NOT A COMMAND

Injection 注入攻擊

注入的共同根源不是某個特殊字元，而是程式把外部資料拼進另一種語言，讓資料有機會改變查詢、命令或模板的結構。真正修正是把資料與指令分離。

80–100 分鐘8 個完整段落資料與指令分離授權環境限定

LEARNING OUTCOME

完成本章後，你能用 Source、Transform、Sink 追蹤注入風險，分辨 SQL、NoSQL、OS Command 與 Template Sink，選擇參數化、固定映射、API 替代與最小權限，並建立安全的程式碼審查清單。

SAFE PRACTICE BOUNDARY

本章不提供可直接攻擊系統的 Payload，也不在外部網站測試。練習只比較本機假資料的「字串拼接」與「參數化」設計，重點是程式碼與測試結果。

01

SOURCE → TRANSFORM → SINK

先找資料在哪裡失去「只是資料」的身分

外部資料可能來自表單、URL、Header、Cookie、Webhook、檔案、訊息佇列或資料庫舊值；經過解碼、轉型與商業邏輯後，最後流入 SQL Driver、Shell、模板引擎、LDAP、搜尋查詢或其他 Interpreter。真正危險的位置是 Sink 把字串當成語言結構解讀。

輸入驗證有價值，但不能靠一份危險字元黑名單防住所有語言、編碼與脈絡。防守優先順序是避免危險 Interpreter、使用結構化 API 或參數化介面、對無法參數化的結構做固定映射，再以最小權限、錯誤處理與測試縮小殘餘影響。

SOURCE不可信資料

表單、Header、Webhook、檔案與舊資料

TRANSFORM解碼與組合

解析、轉型、串接、模板與商業規則

BOUNDARY結構化分離

參數化、型別、固定映射與安全 API

SINK解譯器

SQL、Shell、Template、NoSQL 或搜尋語言

圖 1｜注入資料流 審查重點是每一條 Source 到 Sink 的路，不是只在入口找特殊字元。

02

BIND VALUES

查詢結構由程式決定，使用者只能提供值

SQL Injection 發生在程式用字串拼接建立查詢，讓輸入可能改變原本的語法結構。Prepared Statement／Parameterized Query 先固定 SQL，再透過 Driver 綁定值，使輸入即使包含特殊內容，也只被資料庫視為一個值，而不是新的欄位、運算子或子查詢。

參數化要一路保持到真正 Driver；ORM 的 Raw Query、手寫排序、動態欄名和拼接條件仍可能打破保護。表名、欄名或排序方向通常不能當 Bind Value，應把有限的使用者選項映射到程式內固定字串。資料庫帳號再限制到需要的 Schema、Table 與動作，避免單一缺陷取得超出功能的權限。

RISKY字串拼接

查詢文字與輸入混成同一段語言

RESULT結構可能被改變

黑名單與手動 Escape 容易依脈絡失敗

SAFE固定 SQL

程式碼決定欄位、條件與運算子

BIND輸入只作參數

Driver 依型別傳遞，不進入語法結構

圖 2｜結構與值分離 參數化不是先逃脫字串，而是讓 Driver 知道哪一部分永遠只是資料。

03

MAP, DO NOT CONCATENATE

不能綁定的查詢結構，用固定選項映射

搜尋與報表常需要動態排序、篩選或欄位選擇。錯誤做法是把 sort、direction 或 column 直接放進 SQL；安全做法是把 UI 選項映射到後端定義的 Enumerator，例如 newest 對應 created_at DESC。使用者提供的是產品選項，不是資料庫語言片段。

複雜條件可使用成熟 Query Builder，以型別化節點組合查詢，並對條件數、分頁大小、關聯深度與執行時間設上限。參數化能防語法注入，卻不能防止合法但昂貴的查詢，因此仍需索引、配額、Timeout 與資料範圍授權。

UI OPTIONnewest

使用者選擇可理解的產品語意

ALLOWLIST固定映射

newest → created_at DESC，由程式維護

BUILDER型別化條件

每個節點有允許欄位、運算子與型別

LIMIT資源上限

頁數、深度、Timeout 與配額

圖 3｜動態不等於任意 把產品需求收斂成有限選項，能同時改善安全、效能與可測試性。

04

AVOID THE SHELL

能用函式庫完成的工作，不要交給 Shell 解譯

Shell 是功能強大的語言，會解讀分隔符、變數、重新導向與子程序。若程式把檔名、網域或選項拼成一段命令字串，再交給 Shell，外部資料就可能改變原本命令。OWASP 的第一建議是避免直接呼叫作業系統命令，改用語言或平台提供的檔案、網路、壓縮與圖片 API。

確實無法避免時，使用不經 Shell 的程序 API，把可執行檔與參數以陣列分開傳遞；命令本身固定，參數採正面允許、型別與長度限制，並用低權限專用帳號、隔離工作目錄、資源限制和 Timeout 執行。僅靠 Escape 仍依賴作業系統與 Shell 脈絡，不能作為首選設計。

RISKY命令字串

程式、選項與輸入被拼成同一段 Shell 語言

LIMIT手動 Escape

依 OS、Shell 與參數位置變化，仍可能漏失

PREFER語言函式庫

直接呼叫圖片、檔案、壓縮或網路 API

FALLBACK參數陣列

不啟用 Shell；固定命令、允許參數、低權限

圖 4｜先消除 Shell 最可靠的命令注入防禦，是不要讓外部資料進入一段要被 Shell 重新解讀的字串。

05

VALIDATE THE SHAPE

JSON 是結構，不代表裡面的運算子都安全

NoSQL 系統雖然不用 SQL 字串，仍可能接受包含運算子、條件物件或動態欄位的結構。若 API 把使用者提供的 JSON 直接傳給資料庫 Driver，攻擊者可能提供產品原本沒有打算暴露的查詢能力。風險本質仍是讓外部輸入決定解譯器的結構。

先用 Schema 驗證型別、欄位、巢狀深度與額外屬性，將使用者選項映射成應用程式自己的查詢模型，再由 Builder 產生資料庫條件。不要接受任意 Filter 物件、欄位名稱或正規表示式；同時限制結果數、查詢成本和時間，並使用只能存取該 Collection 的低權限帳號。

JSON外部結構

可能含多餘欄位、巢狀物件與錯誤型別

SCHEMA明確契約

只允許需要的欄位、型別、長度與深度

DOMAIN產品查詢模型

固定的篩選與排序語意，不接受 Driver 語法

DATABASE受限查詢

最小資料範圍、結果數與執行時間

圖 5｜驗證資料形狀 結構化 API 要限制可表達的語言能力，而不是把整個 Driver 介面暴露給外部。

06

KEEP TEMPLATES TRUSTED

使用者提供內容，不應成為伺服器端模板程式

Server-Side Template Injection 發生在應用把外部字串當成模板來源執行，而不是把它當作模板裡的一個變數。安全設計是模板檔由開發團隊控制，使用者內容只透過資料欄位注入，模板引擎維持 Auto-escape，並避免允許任意運算式、物件導覽或方法呼叫。

需要讓使用者自訂通知時，提供有限的 Placeholder 與預覽，不讓他們上傳整段可執行模板。模板注入與 XSS 不同：前者在伺服器模板引擎執行，後者在瀏覽器解譯；兩者都源自資料與程式結構混合，但輸出編碼只能處理瀏覽器脈絡，不能修正伺服器把輸入當模板執行。

SAFE TEMPLATE開發者控制

版本化、審查、固定語法與有限 Helper

UNTRUSTED DATA只作變數

依輸出脈絡編碼，不取得模板能力

UNSAFE外部模板來源

使用者字串被引擎解析成運算式或方法

DESIGN有限 Placeholder

只開放產品需要的欄位，不開放語言本身

圖 6｜模板來源必須受信任 Auto-escape 解決輸出脈絡，不會讓任意伺服器端模板程式變安全。

07

LIMIT THE BLAST RADIUS

預防控制失效時，權限決定最壞後果

參數化能阻止輸入改變查詢結構，但資料庫帳號仍不應是 Owner；只讀頁面不需要 UPDATE，單一服務不需要跨所有 Schema。命令處理程序也不應以 Root 執行或讀取應用 Secret。依功能拆分帳號、Network Route、檔案權限與資料範圍，能讓程式缺陷不直接成為整個平台失守。

資料庫與 Interpreter 錯誤對外回傳一致訊息與事件編號，不洩漏 Query、路徑或堆疊；內部記錄 Sink 類型、程式位置、追蹤 ID、耗時與安全分類，但遮罩參數值中的個資和 Secret。異常 Query Error、程序啟動或模板編譯失敗可成為告警訊號，卻不能取代根因修正。

APPLICATION固定語意

參數化、安全 API、Schema 與 Allowlist

IDENTITY專用服務帳號

依功能與環境拆分，不共用高權限憑證

RESOURCE資料與程序限制

只讀／讀寫分離、工作目錄、CPU 與 Timeout

NETWORK限制可達服務

只連必要資料庫與目的地，保留連線日誌

圖 7｜縮小注入的最壞影響 預防、隔離與偵測疊加，讓單一遺漏不會直接跨越所有資產。

08

REVIEW THE SINKS

用 Sink 清單審查程式，比到處找關鍵字更有效

先列出程式中會解譯其他語言的位置：Raw SQL、ORM 自訂片段、Process／Shell API、模板編譯、搜尋 DSL、LDAP、XPath 與動態設定。對每個 Sink 追蹤資料來源、轉換、參數化方式、允許結構、執行身分、Timeout 和日誌，尤其檢查為了「方便」而使用的 Escape Hatch。

自動化測試以不具攻擊性的邊界資料驗證結構分離：包含引號、空白、Unicode、長字串與保留字的值仍應被當成單一資料，查詢結果只符合精確值；錯誤不洩漏內部資訊；低權限帳號不能做額外動作。再用 Static Analysis 與 Code Review 找出新 Sink，讓安全模式成為共用函式而不是每人重寫。

SOURCE資料從哪來

外部請求、檔案、訊息或舊資料是否可控制

SEPARATION如何分離

參數化、安全 API、Schema 或固定映射

PRIVILEGE以誰執行

資料、程序、檔案與網路是否最小權限

VERIFY如何證明

負向測試、錯誤泛化、日誌與靜態掃描

CHECK YOUR MODEL

先回答，再展開。

輸入驗證能單獨防止所有 Injection 嗎？

不能。首要控制是讓資料與指令結構分離；驗證用來限制產品語意與縮小攻擊面。

ORM 是否保證完全不會 SQL Injection？

不保證。Raw Query、動態欄名、排序與不安全 Escape Hatch 仍可能拼接語法。

為什麼避免呼叫 Shell 比 Escape 更好？

不啟用 Shell 就消除了整套 Shell 語言的解譯面，函式庫或參數陣列的語意更窄。

NoSQL 沒有 SQL，為什麼仍可能注入？

外部 JSON 若能決定 Driver 的運算子或查詢結構，資料仍可能變成指令。

參數化後還需要最小權限嗎？

需要。最小權限限制其他缺陷、設定錯誤或未覆蓋 Sink 發生時的最壞影響。

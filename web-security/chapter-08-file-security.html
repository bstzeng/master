A FILE IS UNTRUSTED

檔案上傳與路徑攻擊

檔案不是一個單純欄位，而是一包名稱、型別、內容、大小、壓縮結構與後續解析行為。真正安全的上傳會驗證、隔離、重新命名、限制處理權限，下載時再做授權。

65–85 分鐘8 個完整段落不可信檔案生命週期授權環境限定

LEARNING OUTCOME

完成本章後，你能建立檔案允許清單、分層驗證型別與大小、隔離不可信內容、避免路徑穿越與公開直連，並為上傳、處理、下載與刪除建立完整權限和日誌。

SAFE PRACTICE BOUNDARY

練習只使用自己建立的無害文字與圖片，不能上傳惡意檔案到任何線上服務，也不提供混淆副檔名、逃逸路徑或繞過掃描的方法。

01

UPLOAD IS ONLY THE START

風險從接收開始，直到下載與刪除才結束

檔案流程包含接收 Metadata 與串流、暫存、驗證、掃描、轉檔、永久儲存、產生預覽、提供下載、保存期限與刪除。每一段可能由不同服務處理，也可能引入新的 Parser；一張看似普通的圖片，後續可能被圖片庫、OCR、CDN 和瀏覽器各解析一次。

先問業務真的需要哪些檔案類型、最大大小、數量與用途。功能如果只需要頭像，就不應接受任意文件；如果只需要 CSV 匯入，就不應直接保存原檔供公開下載。把處理流程畫出來並標示執行身分、網路權限和錯誤處理，能找到比副檔名更深的風險。

RECEIVE限制請求

授權使用者、數量、大小與串流 Timeout

VERIFY多層檢查

副檔名、MIME、內容簽章、結構與安全掃描

PROCESS隔離處理

低權限 Worker、資源上限、重新編碼

DELIVER授權下載

應用 Handler、短效連結、正確 Content-Type

圖 1｜檔案生命週期 每跨過一個處理器都重新驗證假設，並讓原始檔保持隔離。

02

VERIFY, DO NOT TRUST LABELS

副檔名、Content-Type 與檔案內容都只能提供部分證據

瀏覽器傳來的 Content-Type 與原始檔名都由 Client 影響，不能單獨信任。安全流程先正規化名稱並檢查允許副檔名，再由伺服器根據 Magic Bytes／檔案簽章辨識內容，必要時用成熟 Parser 驗證結構。任何結果不一致都應拒絕或送入人工隔離，而不是猜一個最方便的型別。

允許清單只包含業務必要格式，並為每種格式設定大小、頁數、像素、壓縮後大小與巢狀深度。不要把拒絕清單當主要控制，因為格式與解析器持續增加；也不要在驗證前解壓或產生縮圖，否則危險內容已經進入更複雜的處理器。

NAME允許副檔名

正規化後比對，限制長度與字元

DECLAREDContent-Type

只作輔助訊號，不直接信任 Client 宣告

SIGNATURE內容簽章

由伺服器辨識檔案家族，不只看名稱

STRUCTURE成熟 Parser 驗證

限制頁數、像素、巢狀與解壓成本

圖 2｜四層證據 每一層都可能出錯；多層一致加上嚴格業務允許清單才形成可信決策。

03

GENERATE THE STORAGE NAME

保留顯示名稱，不讓使用者決定實體路徑

原始檔名可能包含路徑分隔、控制字元、Unicode 混淆、保留名稱或過長字串，不應直接作為磁碟或 Object Key。應用產生隨機不可預測的 Storage ID，副檔名由驗證後的實際型別決定；原始顯示名稱只作受編碼 Metadata 保存。

檔案優先放在另一個服務或至少 Web Root 外，Object Storage 預設 Private。對外 URL 不直接映射實體路徑，而由應用以物件 ID 查詢授權後串流，或簽發短效、限制方法與內容處置的下載 URL。這讓路徑名稱本身不再等於存取權。

CLIENT原始顯示名稱

不可信 Metadata，可保留但先正規化與編碼

SERVER隨機 Storage ID

由應用產生，不含使用者路徑或名稱

LOCATIONWeb Root 外

私有 Bucket 或隔離檔案服務，預設不可公開

ACCESS應用映射

物件授權後串流，或簽發短效下載權限

圖 3｜顯示名稱不等於儲存路徑 伺服器控制 Storage ID、目錄與型別；使用者名稱只在 UI 安全顯示。

04

PATHS BELONG TO THE SERVER

使用者選物件，不應自由組合檔案系統路徑

Path Traversal 的根源是程式把外部輸入拼進檔案路徑，讓解析後的位置逃出預期根目錄。防守不是只刪掉某段字串，而是根本不接受路徑：Client 傳物件 ID，伺服器從資料庫取得由自己建立的 Storage Key，再由固定根目錄解析。

若業務確實需要相對路徑，先以平台函式做單次一致解碼與正規化，解析成絕對 Canonical Path，確認它仍位於明確 Base Directory 且不是 Symlink／Junction 逃逸，再開啟檔案。不同 OS、Unicode、URL 解碼與大小寫規則不同，應交給成熟 Path API 並寫跨平台測試。

REQUESTObject ID

Client 選擇業務物件，不提供任意路徑

LOOKUP伺服器映射

由資料庫取得自己產生的 Storage Key

RESOLVECanonical Path

固定 Base、正規化、檢查 Symlink 與邊界

OPEN最小權限讀取

只讀必要目錄，不回傳實體路徑

圖 4｜以物件 ID 取代自由路徑 字串前綴比對容易出錯；應使用 Path API、明確 Base 與連結檢查。

05

PROCESS IN QUARANTINE

驗證成功也不代表可以在主應用程序直接解析

防毒、Sandbox 或 Content Disarm & Reconstruction 可增加保護，但不是絕對判斷。高風險文件先進 Quarantine，透過訊息佇列交給低權限 Worker；Worker 沒有應用資料庫憑證、沒有不必要外網、使用獨立暫存目錄、CPU／記憶體／時間上限，處理失敗就保持隔離。

對圖片可讀取後重新編碼成允許格式並移除多餘 Metadata；對文件可依業務採 CDR 或產生安全預覽。原始檔與衍生檔分開標記，只有通過政策的衍生檔能被下載。所有 Scanner 和 Parser 也要補丁管理，因為它們本身就是複雜攻擊面。

QUARANTINE預設不可下載

原始檔隔離，狀態明確且有保存期限

WORKER低權限處理

專用身分、無 Secret、受限網路與資源

ANALYZE掃描或重建

AV、Sandbox、CDR、重新編碼與 Metadata 移除

PUBLISH只發布核准衍生物

來源、版本、檢查結果與雜湊可追蹤

圖 5｜不可信內容隔離處理 即使 Parser 有漏洞，也不應讓它直接取得正式資料、Secret 或整個檔案系統。

06

LIMIT EXPANSION

小檔案可能在解析後消耗巨大空間與時間

只限制 HTTP 上傳大小不足以控制壓縮檔、超大像素圖片、極多頁文件、深層巢狀結構或解析器最壞複雜度。處理前估算解壓後總大小、檔案數與深度，解壓每個 Entry 前驗證目標路徑仍在隔離目錄內，並限制 CPU、記憶體、磁碟與總時間。

上傳與處理採非同步佇列，讓主 Web Request 快速回應狀態，不被昂貴解析阻塞。為每個使用者與租戶設定儲存配額、同時處理數和每日成本；超過限制時可預期地拒絕，而不是等到磁碟填滿或整個服務失效。

INGRESS上傳大小

請求 Body、數量、速率與連線 Timeout

EXPANSION展開後大小

總 Bytes、Entry 數、深度與路徑

PARSERCPU／Memory

像素、頁數、複雜度與處理 Deadline

TENANT配額與併發

儲存量、每日工作與同時 Worker 上限

圖 6｜檔案的四種成本 可用性控制要看處理後成本，不只看原始請求 Content-Length。

07

AUTHORIZE THE DOWNLOAD

知道檔案網址，不代表有權讀取檔案內容

下載 Endpoint 先驗證 Session，再依檔案擁有者、租戶、分享狀態和敏感等級做物件層授權。不能只依一個可預測 URL、Bucket Key 或 Referer 決定權限。公開資產和私有上傳應使用不同 Bucket、Host 或至少明確 Cache Policy，避免 CDN 把私有回應當成共用內容。

回應使用驗證後的 Content-Type、X-Content-Type-Options: nosniff 與安全 Content-Disposition。原始顯示名稱需要正確編碼與長度限制；可執行或主動內容通常強制 attachment，若必須 inline 顯示則放在隔離 Origin，避免與主站 Session 共用同源權限。

REQUESTFile ID

登入主體、租戶、分享脈絡與用途

POLICY物件層授權

讀取、預覽、下載與分享可有不同能力

STORAGE私有取檔

應用讀取或短效簽名 URL，不暴露永久 Key

RESPONSE安全顯示

Content-Type、nosniff、Disposition 與 Cache-Control

圖 7｜下載是新的授權動作 上傳者有權存放，不等於所有人可下載；每次取檔都重新做 Policy。

08

MAKE FILES TRACEABLE

每一個原始檔、衍生檔與下載都要能追溯

記錄 Upload ID、擁有者、租戶、原始顯示名稱的安全版本、實際型別、大小、雜湊、檢查政策版本、Scanner／Parser 版本、處理結果、衍生物關係、儲存位置代碼與保存期限。日誌不直接記錄可能含個資的原文內容或可長期使用的下載 URL。

告警關注大量拒絕、型別不一致、重複危險雜湊、處理 Timeout、單一帳號快速耗用配額、Quarantine 下載嘗試與跨租戶取檔。事件處理要能封鎖雜湊、撤銷分享連結、隔離同批檔案、重建衍生物並通知受影響擁有者。

PREVENT明確政策

類型、大小、名稱、Storage、處理與下載授權

DETECT異常訊號

型別不一致、Timeout、配額與未授權下載

CONTAIN隔離與撤銷

封鎖雜湊、停用連結、隔離原始與衍生檔

RECOVER重新產生

修補 Parser 後重建衍生物並驗證完整性

圖 8｜檔案安全控制表 建立可追蹤 ID 與狀態機，讓問題檔案能被定位、隔離與重新處理。

FIELD ASSIGNMENT

用 40 分鐘完成檔案生命週期表

若網站沒有上傳功能，也可用圖片建置、附件或匯入檔流程完成。

  1. 00–10

    界定業務格式列出必要副檔名、實際 MIME、大小、像素／頁數與保存期限。

  2. 10–20

    畫儲存與處理標出 Quarantine、Worker、Parser、原始檔、衍生檔與外網權限。

  3. 20–30

  4. 30–40

    補上配額與事件設定大小、展開、CPU、儲存上限，以及隔離、撤銷和重建流程。

CHECK YOUR MODEL

先回答，再展開。

瀏覽器回報 image/png 就能相信是 PNG 嗎？

不能。Content-Type 可由 Client 影響，需結合允許副檔名、內容簽章與成熟 Parser。

把檔案放在沒有連結的公開目錄安全嗎？

不安全。沒有連結不是授權；私有檔案應在 Web Root 外並由應用檢查權限。

隨機檔名能完全防止未授權下載嗎？

不能。隨機性只是縱深防禦，下載仍需物件層授權或短效能力。

防毒掃描通過就可以完全信任檔案嗎？

不能。掃描有偵測限制，仍需隔離、Parser 修補、資源上限與安全顯示。

路徑字串只要移除兩個點就安全嗎？

不夠。應避免接受路徑，或使用平台 Path API 正規化、固定 Base 並檢查連結逃逸。
